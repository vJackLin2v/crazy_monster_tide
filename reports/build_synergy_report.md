# 阶段 3 · 高风险构筑组合测试（build_synergy_report）

> 方法：**读代码确认边界 + 新增 12 条单元测试**（`cocos/tests/run.ts` §5m）
> 结论：7 类组合**当前均已存在防护**，没有发现无限递归/无限叠加；1 处需要真机数据确认（击杀回血）。
> 测试结果：**PASS 175 / FAIL 0**（原 163 + 新增 12）

## 1. 弹体数量膨胀 `multi + fan + split`

| 检查点 | 代码事实 | 结论 |
|---|---|---|
| 单次施法弹体数 | 扇射额外弹 `dmg×0.55`（`Battle.ts:783`） | 由份数线性增加 |
| 分裂弹是否继续分裂 | 衍生弹签名里写死 `split: 0`（`Battle.ts:1588`） | **不会递归** |
| 扇形弹能否再次分裂 | 只有命中时 `b.split > 0 && !b.splitDone` 才分裂，且 `splitDone` 置位后不再触发 | 每枚最多分裂 1 次 |
| 单枚分裂上限 | `splitBullets(n) = min(6, 2+n-1)`，3 份 = 4 枚 | **硬上限 6** |
| 派生弹是否触发其他投射物效果 | 衍生弹 `pierce/bounce/chain/split/burn` 全为 0 | 不会二次触发 |

**判定：不存在无限递归。** 上界 ≈ 主弹数 × 5（扇射 3 份时主弹 7 枚 → 理论峰值 35 枚/次施法），建议真机观察帧率，但不构成逻辑 Bug。

## 2. 高频爆发 `echo + rapid + multi`

| 检查点 | 代码事实 | 结论 |
|---|---|---|
| echo 是否递归 | 复读执行体的 rt 里写死 `echo: 0`（`Battle.ts:946`），不会再次入队 | **不递归** |
| 复读次数 | `echoRepeats(n) = min(3, n)` | 最多 3 次 |
| 复读伤害 | `dmg × 0.6`（`Battle.ts:946`） | 不放大 |
| rapid 是否缩短冷却 | 复读时 `skillT[slot] = 0` 后立即恢复 `rt.cd`（`Battle.ts:949-951`） | 复读**不消耗**真实冷却，也不会被 rapid 二次加速 |
| 是否异常高 DPS | 单技能理论峰值 = 基础施法 × (1 + 3×0.6) ≈ 2.8× | 有界 |

**判定：不存在递归爆发。** 但 2.8× 的瞬时爆发可以叠 4 个技能 → 单帧峰值需要真机帧率观察。

## 3. 命中次数膨胀 `chain + bounce + pierce`

| 检查点 | 代码事实 | 结论 |
|---|---|---|
| 执行顺序 | 命中 → 分裂 → 反弹 → 穿透判定（`Battle.ts:1578-1607`） | 固定顺序 |
| 单枚最大命中 | `b.hit` 是 Set，`nearestEnemy(..., b.hit)` 排除已命中；`if (!bounced && b.hit.size > b.pierce + 1) b.life = 0` | 不会重复打同一只 |
| 同怪重复伤害 | 命中集合去重 | 不存在 |
| 无限弹跳 | `b.bounce--` 每次递减，且每次伤害 ×0.8 | 有界且衰减 |
| 穿透/弹跳消耗 | 都是显式递减 | 正确 |

**判定：不存在无限弹跳。** 链式（`while (b.chain > 0)`，`Battle.ts:1564`）同样以 chain 计数为界。

## 4. 续航失衡 `vamp + harvest + lifesteal_l + vampire + reaper`

| 检查点 | 代码事实 | 结论 |
|---|---|---|
| 多个回血入口是否重复结算 | 吸血（`vampire` 4%/份）、击杀回血（`harvest` 1/份）、道具回血（`reaper` 等）分别在不同时机累加 | 分别结算，无重复 |
| 上限 | 所有入口都走 `Math.min(maxhp, hp + x)`（`Battle.ts:1157` 等） | 不会溢出 |
| 每秒回血是否超过承伤 | **无法静态判定**：harvest 每击杀 +1，同屏 30 杀/秒时理论 +30 HP/s；承伤上限约 7.5/s（受无敌帧限制） | ⚠️ **需要真机数据**，这是唯一需要重点观察项 |

**建议（不立即改）**：若真机数据显示"站桩不死"，再加 `harvest` 每秒上限（例如 ≤8 HP/s），而不是削数值。

## 5. 范围伤害 `burn + thunder + overload + rapid`

| 检查点 | 代码事实 | 结论 |
|---|---|---|
| 持续伤害计算频率 | 灼烧按 tick 结算，伤害 = `max(1, round(dmg × burnTickMul(n)))`（`Battle.ts:1101`） | 每份 +10%，封顶 30% |
| 灼烧是否叠加 | `e.burnDmg = Math.max(e.burnDmg, ...)` | **取最大值，不累加** |
| 雷击触发 | `noThunder` 守卫防止同帧重复触发；AoE 伤害走独立结算 | 不会同帧多跳 |
| 分裂弹能否重复触发雷击 | 衍生弹 `chain/bounce/split` 均归零，但**命中回调仍会触发** thunder | 属设计允许（多弹多触发），需真机确认密度 |

## 6. 控制效果 `frost + frostnova + frostring + rapid`

| 检查点 | 代码事实 | 结论 |
|---|---|---|
| 减速是否无限叠加 | `e.slowPct = frostSlowPct(rt.slow)` —— **赋值**，不是 `+=` | 不叠加 |
| 减速上限 | `frostSlowPct = min(0.60, 0.35 + 0.10(n-1))` | 封顶 60%，不会定身 |
| 是否可永久控制 | 每份延长持续时间（`frostDuration = 1.2 + 0.4(n-1)`），但比例不变 | 可延长、不可定身 |
| BOSS 是否可被控 | 当前**没有**对 BOSS 单独限制 | ⚠️ 建议加：BOSS 减速上限 30%，避免"站桩打 BOSS" |

## 9. 结论与建议

**P0/P1：无。** 组合层面没有发现无限递归、无限叠加或重复结算。

**P2（建议改，但需数据/确认）：**
1. BOSS 减速上限 30%（防止永久控制）；
2. `harvest` 每秒回血上限（等真机数据）；
3. 雷击 + 多弹体的同帧触发密度（等真机帧率）。

**P3：** 扇射 3 份 + 分裂 3 份的理论峰值 35 枚/次，建议在真机上观察一局后期帧率再决定是否加全局弹体上限。
