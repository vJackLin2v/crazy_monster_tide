## D-13 移速覆盖 bug（重要教训）

- **现象**：摇杆能拖动、UI 正常，但**角色几乎不动**。
- **根因**：`freshStats()` 用 `Object.assign(s, char.stats)` 合并角色属性，
  而角色数据里写的是 `speed: 0.9`（本意是**倍率**），直接把基础移速 `62` 覆盖成 `0.9 px/s`。
- **修复**：角色数据改用 `speedMul`，由 `freshStats` 计算 `62 * speedMul`；
  并对「绝对值 vs 倍率」的字段做区分。
- **为什么测试没抓到**：旧 E2E 只断言「摇杆出现 / 消失」，**没有断言角色真的位移**。
- **补救**：E2E 新增硬断言「拖动后角色位移 > 20px」「松手后停止移动」，
  并在门禁里断言 `G.stats.speed > 30`。
- **教训**：**UI 出现 != 功能生效**。所有交互都要断言「最终效果」，不能只断言「控件状态」。

## D-19 难度曲线与经济调优（用户第五轮实测反馈）

用户实测反馈：「第 2 波的怪追得很凶」「金币不够」。

### 诊断（真因在公式里，不是"感觉"）

```
旧刷怪公式：每批 n = 1 + floor(wave/2)
  第 1 波 1 只/批  →  第 2 波 2 只/批    ← 强度瞬间翻 2.25 倍（断崖）
旧总刷怪量：第 8 波 545 只 / 第 20 波 1800 只  ← 数值爆炸
敌人解锁：蝙蝠（86 px/s，全场最快）第 2 波就出场，且 86 ≈ 骑士移速 86.4 → 根本躲不掉
```

### 修复

| 项 | 旧 | 新 |
|---|---|---|
| 每批数量 | `1 + floor(wave/2)` | `min(5, 1 + floor(wave/4))` |
| 刷怪间隔 | `max(0.22, 0.85 - wave*0.09)` | `max(0.30, 0.95 - wave*0.04)` |
| **第 2 波总刷怪** | **54 只** | **21 只** |
| 第 20 波总刷怪 | 1800 只 | 600 只 |
| 敌人解锁 | 第 2 波起混合出 | **分波解锁**：史莱姆(1) / 蝙蝠(3) / 哥布林(5) / 骷髅(8) |
| 蝙蝠速度 | 86 px/s（≈玩家速度） | **76 px/s**（玩家 86.4，可躲） |
| 血量成长 | +42%/波 | **+32%/波** |
| 伤害成长 | +16%/波 | **+12%/波** |

### 金币经济

| 项 | 旧 | 新 |
|---|---|---|
| 波次结算 | `10 + 波数 x 6` | `16 + 波数 x 7` |
| 杀怪掉落 | 史莱姆 0 / 蝙蝠 0 / 哥布林 1 / 骷髅 1 / 精英 6 / BOSS 40 | 1 / 1 / 2 / 2 / **15** / **60** |
| 道具价格 | `16 + rand(0,8) + 波数x3` | `13 + rand(0,6) + 波数x2` |
| 模块价格 | `20 + rand(0,10) + 波数x4` | `17 + rand(0,7) + 波数x3` |
| 治疗 / 属性 | `10+w*2` / `22+w*4` | `8+w` / `16+w*3` |

结果：第 1 波结束约 **40~45 金币**（结算 23 + 杀怪约 20），商店最便宜 9 金币 → 前期买得起。

### 新增回归护栏

- `第 2 波不是断崖：20 -> 21 只（<= 1.4 倍）`
- `第 1/2 波只有史莱姆`、`第 3 波才解锁蝙蝠`
- `最快怪速度 < 玩家速度`（可躲是硬条件）
- `第 20 波总刷怪 < 800`（防再次数值爆炸）
- `130 只怪同屏 >= 40 帧`（实测 61 帧）
- `第 1 波商店最便宜 <= 20 金币`

## D-20 商店交互重做（用户反馈「买完东西消失很怪」）

- **决策**：商店改为 **固定 4 货位 + 锁定 + 已购买印记**（参考 Brotato 的货架结构）。
  1. **固定 4 格**：空位也占位显示，列表不跳动（玩家有空间记忆）。
  2. **购买后货位不消失**：保留原位 + 盖「已购买」印章 + 置灰 —— 解决"东西凭空没了"的怪异感。
  3. **锁定**：每个货位可上锁；**锁住的刷新不会被刷掉，并可留到下一波**（Brotato 式）。
  4. 刷新价格递增（2/3/4…）。
- **依据**：用户「商店很奇怪，买完后物品会消失，玩家会觉得很奇怪，最好能参考一下别人是如何实现的」；
  调研见 `docs/ui/reference-library/brotato-analysis.md` 与 D-19 附带检索。
- **实现**：`flow.js`（refreshShop / makeShopItem / toggleLock / carryOver）、`ui.js` `renderShop`。

## D-27 观感基准：ZOOM = 2（单位放大一倍）

- **依据**：用户指令「先调观感 —— 单位 1x 放大到更'有大作感'，同时调整镜头与怪潮密度」。
- **决策**：引入全局渲染缩放 **`ZOOM = 2`**（**必须整数倍，否则像素会糊**）。

| 项 | 1x（旧） | **2x（现）** |
|---|---|---|
| 单位屏幕尺寸 | 32px | **64px** |
| 单位占屏高 | 5.0%（没有主角感） | **10.0%**（Brotato 一类的主角比例 8~13%） |
| 可视世界 | 360 x 640 | **180 x 320**（= 屏幕 / ZOOM） |
| 竞技场 | 540 x 820 | **620 x 940**（留出风筝空间，是可视区的 3.4 x 2.9 倍） |
| 玩家碰撞半径 | 9 | **12**（随视觉同步放大约 1.33x，避免"明明撞上却没伤害"） |
| 敌人碰撞半径 | 8~13 / 精英13 / BOSS20 | **10~14 / 精英17 / BOSS26** |

- **怪潮密度必须联动**（可视面积缩小 4 倍，不调就会糊成一片）：
  - 每批数量 `min(5, 1+floor(w/4))` → **`min(3, 1+floor(w/6))`**
  - 刷怪间隔 `max(0.30, 0.95-w*0.04)` → **`max(0.40, 1.15-w*0.045)`**
  - 生成半径 235~280 → **195~235**（可视半对角线 184，刚好在屏幕外）
  - 第 20 波总刷怪量：600 → **270**
- **伤害数字移到屏幕空间绘制**：字号在世界空间会被放大成糊字 → 改到 `CX.restore()` 之后用屏幕坐标画，
  字始终清晰、大小恒定。
- **受影响**：`engine.js`（视野常量/竞技场/密度/半径）、`render.js`（缩放/摄像机/背景改世界空间/伤害数字）。
- **待观察**：2x 后单屏最多约 50 个格位，是否够"怪潮感"需用户实测（Q18）。

## D-31 相机自适应 cover：**以"复刻原型"为准则**（推翻 D-30 的做法）

- **用户追问**（2026-10-13）：「你无法复刻 HTML 的 DEMO？」
- **结论**：能复刻。**D-30 的做法（把 ZOOM 从 2 调到 3 去补偿）是错的** ——
  那是"用一个大一号的数字掩盖比例问题"，不是复刻。D-30 已作废。

### 真实差异（这才是"看起来小"的原因）

| | HTML 原型 | Cocos（写死 scale=ZOOM 时） |
|---|---|---|
| 适配方式 | stage 固定 360x640（完整容纳） | fitWidth（宽度铺满，高度溢出） |
| 390x844 上可视设计尺寸 | **360 x 640** | 360 x **779** |
| 可视世界 | 180 x **320** | 180 x **390**（竖向多露 22%） |
| 单位占屏高 | 64/640 = **10.0%** | 64x1.083/844 = **8.2%** |

> 单位本身没差多少，**差在"竖向多露出了 22% 的世界"** —— 两者叠加就像"缩了一圈"。
> （我在 2026-10-13 中途曾把这条算错成"单位小 18%"，已纠正：单位按屏高算是 8.2% vs 10.0%。）

### 修法：**自适应 cover 缩放**（不写死数字）

```ts
const vs = view.getVisibleSize();                       // 当前屏幕的可视尺寸（设计单位）
const s  = Math.max(vs.width / VIEW_W, vs.height / VIEW_H);   // cover，保证不露边
this.node.setScale(s, s, 1);                            // World 容器
// 可视世界 = vs / s        位置 = (-vs.w/2 - s*camX, +vs.h/2 - s*(ARENA_H - camY))
```

效果（390x844）：`s = 2.43` → 单位 **84px = 屏高 10.0%**（原型 10.0%）、可视世界 **148x320**（原型 180x320）。
**任何屏幕自动成立，不需要手调数字。**

### 连带动作

- `ZOOM` 回到 **2**（= 原型值），并把 D-30 里被我连带改掉的参数**全部还原成原型参数**：
  竞技场 620x940、生成半径 195~235、刷怪间隔 `max(0.40, 1.15-w*0.045)`、批次 `min(3,1+w/6)`、BOSS 生成距离 186。
- 调试行改为报**【真实值 + 原型对照】**：
  `自适应 x2.43（原型 x2）· 单位 84px = 屏高 10.0%（原型 10%）· 可视世界 148x320（原型 180x320）…`
  —— 以后"像不像原型"可以直接读数，不靠肉眼吵。

### 教训

**"复刻"= 让比例关系在任何条件下都成立，而不是在某一台设备上凑出一个看起来差不多的数字。**

## D-32 UI 全部用 Graphics 画：不引入任何 UI 素材

- **背景**：D-28 定死「UI 只用第一版（Möbelmon 扁平风），不用 ui/kit 素材」。

  3. 不依赖导入器行为（本项目图片被导成 texture 而不是 sprite-frame，见 KI-002）
- **分层**：
  | 文件 | 职责 |
