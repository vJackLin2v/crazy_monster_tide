# 硬规则与红线（每次开工必读）

## 1. 铁律

1. **一次只做一个里程碑**，做完停下等确认。
2. **单次读取 <= 3 个文件**（先查 `AGENTS.md` §2 路由表）。
3. **禁止脑补**：需求冲突 / 数值缺失 / 行为未定义 → 登记待决策项并问用户。
4. **禁止为了跑起来而绕过门禁**（素材门禁 / UI 门禁 / 测试门禁）。
5. **禁止改需求书**：`docs/requirements.md` 只读，问题记录在 §12。
6. **禁止赌博语义**（见 D-06）。
7. **禁止照搬竞品**：美术、文案、数值、UI 一律不得复制现有商业产品。

## 2. 汇报纪律

- 固定格式：`完成 / 验证 / 未完成 / 下一步`。
- 「完成」必须带**真实执行输出**（命令 + 结果摘要 / 截图路径）。
- 禁止使用「应该可以」「理论上没问题」「大概完成」。

## 3. 工程习惯

- 改动前：定位现有实现 → 读调用方 → 读依赖 → 判断影响面 → 给最小方案。
- 核心玩法随机统一走 RNG / Seed，日志打印 seed。
- 伤害计算保持**单一入口**。
- 战斗对象使用对象池。
- 状态更新是交付的一部分：`memory-bank/tasks.md` 未更新 = 任务未完成。

## 3B. 资源纪律（2026-10-12 事故后新增，硬性）

> 事故：用本地 Qwen2.5-VL-3B 做批量目视确认，多实例常驻 GPU/内存，导致用户机器几乎卡死。

1. **禁止在用户机器上批量跑本地大模型**（VLM/LLM/扩散模型）。目视确认单次最多 **1 张图、1 个进程**，
   且必须先告诉用户、跑完立即释放；不得 `nohup` 挂后台、不得并发多实例。
2. **禁止无界后台任务**：任何 `&` 后台进程必须自带超时（如 `timeout 120`）与 PID 记录。
3. **杀进程必须精确**：按 PID / 精确命令行终止，**禁止** `taskkill /IM python.exe` 这类宽匹配
   （会误杀用户自己的进程）。
4. **能代码量的不问模型**：尺寸/坐标/颜色/对比度/断链一律用脚本量（`tests/gate_mvp.cjs`），
   VLM 只用于「几何量不出来」的整体观感判断。
5. 长尾即止损：单个自动化任务超过 **3 分钟**无进展就先停、再排查。

## 3C. 用户环境约束（2026-10-12 用户明确要求）

1. **禁止向 C 盘写入任何文件**。包括：
   - 不要用 `/tmp`（Git Bash 下它指向 `C:\Users\<用户>\AppData\Local\Temp`）→ 用工程内的 `H:\...\.tmp\`
   - 不要跑 `npm install`（缓存写 C 盘）→ 复用 `H:\AI-game\xingnang\cocos_port\node_modules`
   - 跑外部工具时先设 `TEMP`/`TMP`/`TMPDIR` 指向 H 盘
2. **不要写过多测试**。用户明确要求：够用就行，别为了覆盖率造测试。
   已有测试只在**关键规则回归**时补充（如 D-13 倍率、KI-001 回收），不要新建测试套件。

## 4. 已知踩坑（继承自同类工程，勿重复踩）

| # | 坑 | 规则 |
|---|---|---|
| 1 | 改了 PNG 但引擎用缓存 → 画面静默失效 | 素材变更后必须走引擎侧重新导入 / 刷新流程 |
| 2 | 非整数倍缩放 → 像素抖动 / 糊边 | 像素素材整数倍缩放 |
| 3 | 测试假设干净状态 → 偶发失败 | 存档 / 进度类测试必须先重置，并连跑两次 |
| 4 | 全局时间倍速不还原 → 影响其它场景 | 倍速 / 全局状态用完必须还原 |

## 5. 未登记即不存在

任何新规则、新系统、新依赖、新素材，未进 `docs/` 或 `memory-bank/` 的，视为不存在，不得在代码里偷偷引入。

| 5 | 用**旧字符串**当编译标记 → 工具立刻返回 OK，其实没编译 | 触发编辑器编译时，标记必须是**新代码独有**的（改了才有的词）；工具说 0s 通过就要怀疑 |
| 6 | 预览可视高度是 **760**，不是设计稿的 640 | 所有"贴底"的元素（技能栏/底部按钮）必须**按底部换算** `VH - 离底距离`，不能写设计稿的绝对 y，否则会悬空 120px |
| 7 | 同一个节点加两个 `Graphics` → 图标画不出来 | `panel()` 内部已建 Graphics；要再画图标必须新建**子节点** |
| 8 | `text()` 是单行高节点，开了自动换行会把第二行裁掉 | 单行标签要么限宽截断（`fit()`），要么显式加高 |
| 9 | **`Battle.start()` 不保证在 `startRun` 之前跑** | 菜单里 Battle 节点是 inactive，Cocos 不会调 `start()` → `cam/world` 都没建。`startRun` 必须**自保** `if (!this.cam) this.buildTree()`，且 `buildTree` 要**幂等**（重复调用会产生第二套 World/Camera，画面直接对不上） |
| 10 | `Graphics.ellipse() + fill()` 会让 Cocos 卡死 | 椭圆填充改用 `circle + fill` + 节点 `setScale(1, 0.42, 1)` 压扁 |
| 11 | `resources.load()` **不接受扩展名** | `'art/audio/battle.ogg'` 会报 "Bundle resources doesn't contain…"。必须去掉 `.ogg/.wav/.png` 再加载（图标那边早就这么做了，音频漏了） |
| 12 | 「没载入就先记状态」导致功能永不生效 | BGM 的 `bgm()` 在 clip 未载入时就把 `curBgm` 记下了 → 之后同样调用被"同一首"挡掉，**永远不播**。要记"想要的状态"，等载入完补播 |
| 13 | **放大像素角色 ≠ 放大帧框**：32×32 单位帧里角色本体只有 13×15（约 40%），把框从 96 加到 128 后角色本体仍只有 52×60 | 要真正变大必须**先裁掉透明留白**（`portrait.png`）再按整数倍放大；判断"够不够大"要量**角色本体的像素尺寸**，不是节点尺寸。见 D-36 / `ui/CharLayout.portraitFit()` |
