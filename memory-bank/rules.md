# 硬规则与红线（每次开工必读）

## 1. 铁律

1. **一次只做一个里程碑**，做完停下等确认。
2. **单次读取 <= 3 个文件**（先查 `AGENTS.md` §2 路由表）。
3. **禁止脑补**：需求冲突 / 数值缺失 / 行为未定义 → 登记待决策项并问用户。
4. **禁止为了跑起来而绕过门禁**（素材门禁 / UI 门禁 / 测试门禁）。
5. **禁止改需求书**：`docs/requirements.md` 只读，问题记录在 §12。
6. **禁止赌博语义**（见 D-06）。
7. **禁止照搬竞品**：美术、文案、数值、UI 一律不得复制现有商业产品。

## 2. 汇报纪律

- 固定格式：`完成 / 验证 / 未完成 / 下一步`。
- 「完成」必须带**真实执行输出**（命令 + 结果摘要 / 截图路径）。
- 禁止使用「应该可以」「理论上没问题」「大概完成」。

## 3. 工程习惯

- 改动前：定位现有实现 → 读调用方 → 读依赖 → 判断影响面 → 给最小方案。
- 核心玩法随机统一走 RNG / Seed，日志打印 seed。
- 伤害计算保持**单一入口**。
- 战斗对象使用对象池。
- 状态更新是交付的一部分：`memory-bank/tasks.md` 未更新 = 任务未完成。

## 3B. 资源纪律（2026-10-12 事故后新增，硬性）

> 事故：用本地 Qwen2.5-VL-3B 做批量目视确认，多实例常驻 GPU/内存，导致用户机器几乎卡死。

1. **禁止在用户机器上批量跑本地大模型**（VLM/LLM/扩散模型）。目视确认单次最多 **1 张图、1 个进程**，
   且必须先告诉用户、跑完立即释放；不得 `nohup` 挂后台、不得并发多实例。
2. **禁止无界后台任务**：任何 `&` 后台进程必须自带超时（如 `timeout 120`）与 PID 记录。
3. **杀进程必须精确**：按 PID / 精确命令行终止，**禁止** `taskkill /IM python.exe` 这类宽匹配
   （会误杀用户自己的进程）。
4. **能代码量的不问模型**：尺寸/坐标/颜色/对比度/断链一律用脚本量（`tests/gate_mvp.cjs`），
   VLM 只用于「几何量不出来」的整体观感判断。
5. 长尾即止损：单个自动化任务超过 **3 分钟**无进展就先停、再排查。

## 4. 已知踩坑（继承自同类工程，勿重复踩）

| # | 坑 | 规则 |
|---|---|---|
| 1 | 改了 PNG 但引擎用缓存 → 画面静默失效 | 素材变更后必须走引擎侧重新导入 / 刷新流程 |
| 2 | 非整数倍缩放 → 像素抖动 / 糊边 | 像素素材整数倍缩放 |
| 3 | 测试假设干净状态 → 偶发失败 | 存档 / 进度类测试必须先重置，并连跑两次 |
| 4 | 全局时间倍速不还原 → 影响其它场景 | 倍速 / 全局状态用完必须还原 |

## 5. 未登记即不存在

任何新规则、新系统、新依赖、新素材，未进 `docs/` 或 `memory-bank/` 的，视为不存在，不得在代码里偷偷引入。
