# 硬规则与红线（每次开工必读）

## 1. 铁律

1. **一次只做一个里程碑**，做完停下等确认。
2. **单次读取 <= 3 个文件**（先查 `AGENTS.md` §2 路由表）。
3. **禁止脑补**：需求冲突 / 数值缺失 / 行为未定义 → 登记待决策项并问用户。
4. **禁止为了跑起来而绕过门禁**（素材门禁 / UI 门禁 / 测试门禁）。
5. **禁止改需求书**：`docs/requirements.md` 只读，问题记录在 §12。
6. **禁止赌博语义**（见 D-06）。
7. **禁止照搬竞品**：美术、文案、数值、UI 一律不得复制现有商业产品。

## 2. 汇报纪律

- 固定格式：`完成 / 验证 / 未完成 / 下一步`。
- 「完成」必须带**真实执行输出**（命令 + 结果摘要 / 截图路径）。
- 禁止使用「应该可以」「理论上没问题」「大概完成」。

## 3. 工程习惯

- 改动前：定位现有实现 → 读调用方 → 读依赖 → 判断影响面 → 给最小方案。
- 核心玩法随机统一走 RNG / Seed，日志打印 seed。
- 伤害计算保持**单一入口**。
- 战斗对象使用对象池。
- 状态更新是交付的一部分：`memory-bank/tasks.md` 未更新 = 任务未完成。

## 4. 已知踩坑（继承自同类工程，勿重复踩）

| # | 坑 | 规则 |
|---|---|---|
| 1 | 改了 PNG 但引擎用缓存 → 画面静默失效 | 素材变更后必须走引擎侧重新导入 / 刷新流程 |
| 2 | 非整数倍缩放 → 像素抖动 / 糊边 | 像素素材整数倍缩放 |
| 3 | 测试假设干净状态 → 偶发失败 | 存档 / 进度类测试必须先重置，并连跑两次 |
| 4 | 全局时间倍速不还原 → 影响其它场景 | 倍速 / 全局状态用完必须还原 |

## 5. 未登记即不存在

任何新规则、新系统、新依赖、新素材，未进 `docs/` 或 `memory-bank/` 的，视为不存在，不得在代码里偷偷引入。
