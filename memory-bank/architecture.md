## 2. 与引擎无关的硬约束 `[定]`

- 逻辑分辨率 **360 x 640**，竖屏，fitWidth。
- 纹理过滤 **Nearest**；像素素材**只允许整数倍缩放**（否则糊边）。
- 战斗对象数量可能上百：需要**对象池**，避免每帧创建 / 销毁。
- 随机统一走 RNG / Seed（`core/Rng.ts`，mulberry32）。
- 伤害计算必须**单一入口**（`game/SkillCalc.ts` → `Battle.dealDamage`）。
- **不往 C 盘写任何文件**（用户环境约束）。
- UI **全部用 `Graphics` 绘制**，不引入任何 UI 素材（D-32）。

## 3. 模块边界（实际工程结构）

```
cocos/assets/scripts/
  core/      纯逻辑基础：常量表（唯一数值来源）、可复现随机      ← 不 import cc
  data/      配置表：技能/模块/道具/角色/敌人/属性/帧清单        ← 不 import cc
  game/      玩法逻辑：属性计算、模块叠算、一局状态、战斗公式    ← 不 import cc
  engine/    与引擎打交道的通用件：资源加载、帧动画、相机、摇杆
  battle/    战斗主体：玩家 / 怪潮 / 技能 / 子弹 / 范围 / 掉落 / 波次
  ui/        画面与交互（菜单 / 模态 / HUD / 管理屏）
  GameRoot.ts 入口：屏幕切换与流程编排
```

**分层意图**：`core / data / game` 三层**刻意不依赖 `cc`**，
于是可以在**不开编辑器**的情况下做类型检查（`tsconfig.check.json`）与单元测试。
这是本工程最重要的工程约束 —— 玩法逻辑的回归**不需要打开 Cocos 编辑器**。
