### #5 经验系统（影响最大）

**真因**：`RunState.addKill()` 里直接 `addExp(exp)` —— **击杀瞬间经验就到账**，
地上的经验球纯装饰，而且捡起来还会再加一次（重复计算）→ 拾取范围形同虚设。

| 改动 | 内容 |
|---|---|
| `addKill` | 只加击杀数与金币，**不再给经验** |
| `Battle.updateGems` | 经验只在**捡起时**给（拾取半径有作用了） |
| 波次结束全屏吸取 | 基础宝石照常吸，**经验 × 0.5**（用户要求） |

黑盒实测（把玩家挪到角落，看球累积）：
```
1.5s | 场上 4 个球 | 经验 2（击杀 6）
3.0s | 场上 7 个球 | 经验 2（击杀 9）   ← 击杀涨了、球涨了，经验没涨 = 只在捡时给 ✓
4.5s | 场上 7 个球 | 经验 0（击杀 11）  ← 升级消耗，之后不再增加（玩家已远离）
```

### 三档视口的诚实结论

```
375x812 / 390x844 / 412x915 / 360x640  →  可视世界**全都是 360x760**，越界元素 0，页面错误 0
```

**这个测试没有真正改变宽高比** —— Cocos 预览页把画布尺寸锁死了（我试过直接改 canvas 尺寸

所以**真·多机型验证还没做**，需要：真机 / 微信开发者工具 / **Web 构建产物**（构建产物是自适应的）。

**已做的替代验证**：静态扫描所有 `at()/A()` 的 y 参数 —— 全部落在上半屏（max 230），
底部元素一律用 `VH - X` 锚定。**这条能防住"在非 640 屏上错位"这一类问题**，本轮就是靠它发现了抽屉没贴底。
