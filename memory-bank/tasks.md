| `data/UnitFrames.ts`、`VfxFrames.ts` | 帧清单（**从磁盘实际文件生成**，不手写） |

### 关键实现点

- **坐标约定成体系**：世界 y 向下（与原型一致，方便对照），Cocos y 向上；
  `Camera2D` 里写了完整推导（Canvas 原点在屏幕中心 → `P = (-180 - ZOOM*camX, 320 - ZOOM*(ARENA_H - camY))`）
- **KI-001 在 Cocos 侧正面实现**：`if (e.dead) { e.deathT += dt; continue; }` 放在循环最前
- **BOSS 波推进**：BOSS 波没有倒计时，靠 `bossDefeated` 标志推进（自测发现并修掉的一个死锁）
- **美术走 resources/**：Cocos 只有 `assets/resources/` 能在运行时 `resources.load`。
  9.3MB 会超微信主包 4MB 限制 → **构建阶段必须改成 Asset Bundle / 分包**（已记为待办）

### 验证（不依赖编辑器）

```

tsc -p tsconfig.cc.json      -> 0 错误（画面层：语法 + 未定义标识符检查，用 cc 桩类型）
```

> 这类问题若不拦，会等到你打开编辑器才爆。

## M9 交付物

用户指令：「先调观感 —— 单位 1x 放大到更'有大作感'，同时调整镜头与怪潮密度」。

### 先算后做（不拍脑袋）

```
屏幕 360x640 ｜ 单位原生 32px
 1x → 32px 占屏高 5.0%   横向排 11 个   ← 没有主角感
 2x → 64px 占屏高 10.0%  横向排 5.6 个  ← 落在 Brotato 一类的主角比例区间（8~13%）
 3x → 96px 占屏高 15.0%  横向排 3.8 个  ← 偏大，怪潮放不下
→ ZOOM = 2（必须整数倍，否则像素糊）
```

### 三处联动（单独放大 = 挤爆屏幕，必须一起改）

| 项 | 旧 | 新 |
|---|---|---|
| 渲染缩放 | 1x | **2x** |
| 可视世界 | 360x640 | **180x320** |
| 竞技场 | 540x820 | **620x940**（风筝空间更足） |
| 每批刷怪 | `min(5, 1+⌊w/4⌋)` | **`min(3, 1+⌊w/6⌋)`** |
| 刷怪间隔 | `max(0.30, 0.95-w*0.04)` | **`max(0.40, 1.15-w*0.045)`** |
| 生成半径 | 235~280 | **195~235**（可视半对角线 184，刚好屏外） |
| 第 20 波总刷怪 | 600 | **270** |
| 玩家/敌人碰撞半径 | 9 / 8~13 | **12 / 10~14**（同步放大，避免"撞上没伤害"） |

### 顺带修的一个体验问题

**伤害数字原本画在世界空间** → 被 2x 放大后变成糊字。
改为 `CX.restore()` 之后用**屏幕坐标**绘制，字号恒定、边缘清晰。

### 验证

```
玩家流程 E2E: 90 PASS / 0 FAIL · 零控制台错误
静态门禁    : 72 PASS / 0 FAIL
```

新增观感断言：

```
PASS 渲染缩放 ZOOM=2x（整数倍，像素不糊）
PASS 单位占屏高 10.0%（参考区间 8~13%）
PASS 可视世界 180x320（= 屏幕 / ZOOM）
PASS 竞技场 620x940 是可视区的 3.4x2.9 倍（留出风筝空间）
PASS 玩家碰撞半径 12（随视觉放大同步上调）
PASS 第 20 波总刷怪量 270（ZOOM=2 后同步下调）
PASS 130 只怪同屏（ZOOM=2）：1 秒 61 帧
```

**同屏压力**：37 敌人 + 9 弹幕 + 29 特效，零错误；战斗区颜色种类 7,542 → **10,391**
（画面上"东西"明显变多了）。
