## 2. 战斗地面

### 先说尺寸（上一版错了）

`Const.ts`：`ARENA_W = 620`、`ARENA_H = 940`、`ZOOM = 2`、`VIEW_W/VIEW_H = 180×320`。
也就是说**相机在 620×940 的场地里滚动**，一屏只看得到 180×320 世界单位。
上一版给的 360×640「整屏图」根本铺不满场地——已删，改为**按世界坐标 1:1 出图**，游戏里 1 纹理像素 = 1 世界单位 = 2 屏幕像素。

### 对齐 Brotato 的做法

| 项 | 现行实现（`Battle.ts buildTree`） | 新 |
|---|---|---|
| 底 | 24px 棋盘格，蓝调 #131C36 / #17233D / #1A2846，360×640 里 **405 格** | **近纯色** #252430，无网格 |
| 纹理 | 每格 3×3 白点（高频） | 无高频纹理；只有 4 档暗角（像素风分档，不做平滑渐变） |
| 细节 | 程序碎石层（`GRAVEL`） | 44 个碎石簇（每簇 3~8 颗）+ 120 颗散落，对比 ±10 |
| 边界 | 橙色 2px 描边 | 3 层边：4px 深色 + 2px 灰 + 1px 暖色 #604624 |
| 色彩 | 偏蓝（与 UI 的紫灰不搭） | 紫灰（#252430，紧贴 UI 的 bg1 #262636） |

**为什么这样不花**：像素游戏里最抢眼的是「高频对比」——棋盘格每 24px 一次明暗跳变，等于给全屏铺了层噪点；
改成近纯色后，高频能量只剩角色、怪物、投射物，这是 Brotato 同样在做的事（背景几乎不带花纹）。

## 3. 首页背景（v3 · 暮色城门）

**用户反馈**：前一版是「晴天草地」，太概念、太扁平；要参考同类型游戏、适配当前 UI（深紫灰 + 橙强调）。

**参考取向**（Halls of Torment / Brotato / Vampire Survivors 的菜单背景共性）：
暗场景 + **单一暖光源** + 一个巨大剪影做构图锚点 + 上方留空给标题。不用白天。

| 项 | 值 |
|---|---|
| 结构 | 星空 → 落日 → 远山 → 城墙/双塔/拱门 → 崖壁前景 → 火堆 |
| 天空 | 8 段色阶 + **Bayer 4×4 抖动**过渡（不是平滑渐变） |
| 光源 | 落日（城门后）+ 火堆（右前景）+ 塔窗暖光，全部用 UI 强调色系 #E6984A / #F5A623 |
| 主体 | 城墙砖缝、城垛、尖顶旗、拱门暖光溢出 |
| 前景 | 崖壁 + 小路 + 草簇 + 三块大石，避免下半屏死黑 |
| 暗角 | 38 层 alpha 递进 |
| 适配 | 主色 #0F0D18 ~ #842C32 与 UI 的 #262636 / #F5A623 同族；上半屏压暗，白字标题可读 |

| [Lospec · Perspective 分类](https://lospec.com/pixel-art-tutorials/tags/perspective) | 空气透视的通用做法 |

| [a327ex · Orblike SNKRX 剖析](https://a327ex.com/logs/orblike-snkrx-archeology) | 背景层如何给玩法让位 |

归纳出 6 条，并逐条落到这张图上：

| # | 原则 | 本图怎么落 |
|---|---|---|
| 1 | **值域分组**：整图只留 4~5 个明度带，层内收敛、层间拉开 | 天空 9 阶 / 远山 #2E2640 / 城墙 #1C1626 / 地面 #12101A / 前景 #09080E |
| 2 | **空气透视**：远的更亮更灰，近的更暗更实 | 远山比城墙亮 14 阶，前景压到接近黑 |
| 3 | **单一暖光源 + 焦点在三分位** | 落日放在右下 1/3（x=250），全部边缘光都朝它 |
| 4 | **前景框景**：左/右压一块大剪影，制造纵深与`窗口感` | 左侧崖壁 0~46px 贯穿 300~640 |
| 5 | **抖动只用于天空与雾** | 天空 9 阶 Bayer 4×4；雾带用隔行点阵；地面/墙体一律平涂 + 颗粒 |
| 6 | **不用纯黑**：最暗也留 6~10 的亮度 | 前景 #09080E（不是 #000），暗角只压 30 alpha |

另外两条工程约束：

- **上半屏留空**：y<300 只有天空和星星，标题/副标题不会压到细节；
- **低频优先**：所有纹理都控制在 1~2px、对比 ≤6，避免和战斗特效抢注意力（这是上一轮`太花`的教训）。

## 3.6 战斗地面 v2（SDXL 打底 + 程序化收敛）

用户要求「类似土豆兄弟那种简单的、风格统一」。SDXL 直出的地面（石砖 / 鹅卵石 / 草地）都**太碎**，
所以改成「SDXL 只提供低频起伏，高频全部由程序控制」：

| 步骤 | 参数 |
|---|---|
| 采样 | `fl2_702`（SDXL 泥土）→ 缩到 620×940 → 高斯模糊 **14px** |
| 对比压缩 | 以中灰为轴 ×0.5 |
| 降饱和 | 20% 保留（其余转灰） |
| 与 UI 底色混合 | SDXL 仅占 **15%**，其余 85% 是 #252430 |
| 暗角 | 连续（1.6 次幂）×9，**不做分档**（分档会画出一圈圈椭圆） |
| 碎石 | 40 个簇 + 120 颗散落 + 14 块大石，亮面 (72,70,90) / 暗面 (22,21,30) |
| 边界 | 4px 深 + 2px 灰 + 1px 暖色 |
| 量化 | 32 色 |

效果：地面接近纯色，只有极低频的不均匀 + 稀疏碎石，**视线全部留给角色和特效**。

### 2026-10-20 第九轮：按移动端布局标准重排首页

**用户反馈**：按钮上提后底部又空了，要求「找个设计标准按标准来」。

#### 采用的 4 条标准

| 标准 | 内容 | 出处 |
|---|---|---|
| 触控目标 | 最小 44×44pt（Apple）/ 48×48dp（Material）；本项目全部按钮 ≥ 80px（2×） | [Apple HIG](https://developer.apple.com/design/human-interface-guidelines/)、[WCAG/Material 对照](https://buildwithaccess.com/blog/touch-target-size-mobile-accessibility-wcag) |
| 拇指热区 | 主操作放屏幕下 1/3、居中，单手可及 | [Thumb zone](https://timgraf.com/ux-design/designing-for-the-thumb-zone-a-modern-guide-to-mobile-ux-that-respects-human-anatomy/)、[移动游戏 UX](https://gamedesign.gg/articles/mobile-game-ux-design/) |
| 8pt 网格 | 间距/尺寸取 8 的倍数（细粒度取 4） | [8pt grid](https://wpdean.com/what-is-the-8-point-grid-system/) |
| 安全区 | 左右 16；底部留 24（避开手势条） | [iOS/Android 布局指南](https://www.uiugur.com/blog/ios-vs-android-mobile-layout-guide) |

#### 与标准的对应（1× = 360×640）

| 元素 | y 区间（1×） | 尺寸 | 与标准的对应 |
|---|---|---|---|
| 标题 | 78..120 | 54px(2×) | 上 15% 内，避开顶部安全区 |
| 副标题 | 128..140 | 15px | 8pt 网格 |
| 存档卡 | **176..380** | 328×204 | 填掉中段空白，内容用真实数据 |
| 继续游戏 | 452..508 | 328×56 | 主 CTA，落在下 1/3 拇指区 |
| 开始新游戏 | 520..564 | 328×44 | 次级，间隔 12（8pt） |
| 图鉴 / 设置 | 576..616 | 160×40 | 最小触控 40>36，左右各 16 边距 |
| 底部安全 | 616..640 | 24 | 避开手势条 |

**为什么中间放存档卡而不是留白**：标准要求 CTA 贴底 + 主操作在拇指区，
那么标题与 CTA 之间必然出现一段空白；解决办法只有两条——把标题下移，或往里填真实内容。
「继续游戏」本身就需要上下文（谁、第几波、什么 Build），所以填存档摘要最合理，也顺手解决了空白。

> ⚠️ 前提：这要求游戏有存档。当前工程**没有存档系统**，所以这张卡是设计稿；
> 若暂不做存档，应把「继续游戏」整个去掉，按钮组整体上移一档（48px），而不是留白。

### 2026-10-20 第二十二轮：背景「没生效」的真因 + 接入

用户反馈：主菜单和地图背景都没生效。查下来是**两个独立问题**：

| # | 问题 | 证据 | 修法 |
|---|---|---|---|
| 1 | 背景图 meta 是 `"type": "texture"`，**没有 spriteFrame 子资源** | `art/bg/battle-floor-620x940.png.meta` 里 subMetas 只有 `6c48a/texture` | 不走 `resources.load(.../spriteFrame)`，改用 `Assets.loadBg()`（内部 spriteFrame→texture 双路回退） |

新增接口（`engine/Assets.ts`）：

```ts
static async loadBg(name: string): Promise<SpriteFrame | null>   // art/bg/<name>，带缓存
```

调用点：

- `battle/Battle.ts buildTree()` → `Assets.loadBg('battle-floor-620x940')`
- `ui/MenuScreens.ts buildMenu()` → `Assets.loadBg('home-bg-360x640')`
