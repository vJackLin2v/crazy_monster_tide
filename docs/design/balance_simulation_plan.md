# 数值模拟与平衡计划（balance_simulation_plan）

## 1. 现阶段能做的与不能做的（如实说明）

| 能力 | 状态 |
|---|---|
| 解析式基线（需要多少 DPS / 承伤） | 可做（已在 reports/balance_report.md） |
| 浏览器内自动跑战斗并读遥测 | **部分可做**：曾失败，原因是强制跳波时玩家会死、波不结束 → 没有记录 |
| 真机帧率/手感 | **不能做**（无设备） |

本轮新增了遥测字段 dmgDealt + 调试时间倍速，但**尚未跑通自动 A/B**。因此本计划只定义方法，不产出假数据。

## 2. 测试矩阵

### 技能
| 场景 | 观测 |
|---|---|
| 单技能裸装 | DPS、命中数、存活 |
| +1 / +3 黑科技 | DPS 增幅、弹体数 |
| +2 道具 | DPS 增幅 |
| 对普通/精英/BOSS | 击杀耗时 |
| 高密度怪群（第 15 波） | 同屏存活、帧率 |

### 黑科技
触发次数/秒、递归深度、同帧伤害事件数、弹体峰值、对 BOSS 生效性。

### 难度
每档跑 5/10/15/20 波，记录：难度、波次、耗时、生成数、击杀数、存活、玩家血量、DPS、承伤、金币、等级、构筑、fps。

## 3. 数据回收方式（可执行）

1. 在游戏里完整打一局（不用脚本跳波）→ 控制台执行 `__logDump()`；
2. 每波记录已含：wave / sec / kills / aliveMax / hp / dmgTaken / **dmgDealt**（本轮新增）；
3. 难度上线后，记录里再加 difficulty 字段；
4. 收集 3~5 局（不同难度）后做 A/B 与难度曲线校准。

## 4. 判定标准（先定规则，再看数据）

| 指标 | 目标 |
|---|---|
| 第 10 波清场率（存活 <10） | ≥80% |
| 第 15 波死亡占比（普通难度） | 30~50% |
| 第 20 波通关率（普通） | 20~35% |
| 地狱通关率 | 3~8% |
| 单帧伤害事件 | < 120 |
| 同屏弹体峰值 | < 120 |
| 后期 fps（中端机） | ≥45 |

## 5. 若数据不达标，调整优先级

1. 先调**承伤**（dmgPerWave / 无敌帧），因为它最直接决定生死；
2. 再调**刷怪密度**（interval / 同屏上限）；
3. 最后才调 HP 成长（它对"打得动"影响最小，因为玩家 DPS 成长更快）。

## 6. v3 追加：审核要求的测试项（开发后必须做）

| 项 | 方法 | 判定 |
|---|---|---|
| 困难经济压力 | 模拟/真机跑 100 局（脚本不够就人工 20 局） | 第 12 波前不应因金币枯竭而无法构筑 |
| 噩梦 BOSS 召唤 | 构造 BOSS 血量从 75% 快速掉到 20% | 两次召唤间隔 >=12s，同屏 <=6，预警 1.2s 可见 |
| 地狱精英生成 | 检查 5/8/11/14/17/20 波 | 每波至少 1 只精英，词缀 2 个且不重复 |
| 回血公式 | 单测：基础回血 x healMul 与预算取 min | 不出现"倍率 + 预算"双重削弱 |
| 商店价格 | 地狱第 1/10/20 波取价 | = 基础 x1.35 x (1+0.02x(w-1))，封顶 +35% |
| 存档迁移 | 用 wins=0 / wins=3 两种旧档 | 不覆盖已有字段，困难按规则补 |
| 无尽徽章 | 重复进 30/40/50 波 | 每档每里程碑只记一次 |
| 模块递归 | 6 条单测（见 damage_event_interface §4） | 全部通过 |
