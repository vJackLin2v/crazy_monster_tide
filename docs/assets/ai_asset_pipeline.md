# AI 素材管线评估（2026-10-20）

> 触发：用户提供 B 站视频 [BV13oJi6zEHd](https://www.bilibili.com/video/BV13oJi6zEHd/)，
> 问「能否接入某些软件来生成技能特效 / 角色 / 图标」。
>
> **结论先行**：能，但不是视频里那条路。视频证明的是「模型写代码生成画面」，
> 我们真正要的是「生成 32×32 像素资产」——两条工具链不同。
> 最该用 AI 的地方也不是"加新内容"，而是**把阻断素材换掉**（见 §2）。

> **v2 增补（2026-10-20 17:20）**：本会话重新下载并抽帧复核了该视频（证据
> `.tmp/video/sheet.png`），§1 结论无误；另补了 2026-10 的软件/价格/LoRA 三路线检索，
> 见 **§10**。§6/§7 的部分估值已被 §10.4 修正（生成费比原估低一个数量级）。

## 1. 视频实际内容（已抽帧核对，非猜测）

| 项 | 事实 |
|---|---|
| 题材 | 4 条短提示词 + 4 条长提示词，各出 4 件作品（共 8 件）：节气海报、面包店海报、海岛 3D、微缩小镇、中式建筑群、雪山牧场、网站复刻 |
| 技术 | 全部 HTML/CSS/Three.js **代码直出**；页面带轨道相机 UI |
| 评的是 | 前端 / 3D 代码能力（片尾统计 18 件作品、排名 8 / 48），不是贴图或精灵生成能力 |
| 可用点 | ① 写 Shader / 粒子 / 程序化场景代码 ② 3D 场景当宣传图、主菜单背景 ③ "描述 → 可运行画面"的迭代速度 |
| 不可用点 | 不产出 2D 像素角色 / 图标；不解决一致性、授权、32×32 归一化 |

**一句话**：这是一次「模型能写视觉代码」的演示，不是「模型能画游戏素材」的演示。
把它当"程序化特效与场景"的证据用，是准确的；当"角色/图标生成器"用，是误读。

## 2. 需求 × 能力映射（按"能不能解除上架风险"排序）

| 需求 | 现状 | 视频能力够吗 | 真正需要的 | 优先级 |
|---|---|---|---|---|
| **角色 / 怪物** | 24 个单位、534 帧，**全部来自阻断主池**（D-26，上架前必须重裁） | ❌ 不对口 | 像素模型直出 / 云端微调 / 3D 烘焙 | 🔴 最高 |
| **图标** | 268 张（含 65 张 relic 与技能/属性图标，其中主池部分 129 张需替换） | ❌ 不对口 | 像素或矢量模型 + 统一化 | 🟠 高（快赢） |
| **技能特效** | 947 帧、85 个组件，多数 CC0 / 可商用（少数需署名）——**其实不缺** | ✅ 最对口（写 shader / 粒子代码） | 程序化特效 + 少量关键帧 | 🟡 中（最便宜） |
| 主菜单 / 宣传图 | Xianxia CC0 视差图 | ✅ 对口 | 3D 场景直出 + 截图 | 🟢 低 |

**反直觉的地方**：我们最缺的（单位，且是阻断素材）恰好是 AI 最不擅长的；
我们最不缺的（VFX 已有 947 帧可商用）反而是 AI 最擅长的。
所以不要按"哪个效果酷"排期，要按"哪个能上架"排期：**图标 → 单位 → 特效**。

## 3. 三条可落地管线

### 3.1 图标（先做，1~2 天出第一版）

```
风格锚定 → 批量生成 → 统一化 → 人工挑选 → VLM 复核 → 写 IconMap
```

| 工具 | 适合 | 要点 |
|---|---|---|
| [PixelLab](https://www.pixellab.ai/docs) | 像素直出、UI 元素、8 向、Aseprite 插件、API | FAQ 明确可商用，但**禁止用其输出再训练模型** |
| [Retro Diffusion](https://retrodiffusion.ai/) | 专训像素模型（网格对齐、限色板） | 也可在 Scenario 里调用 |
| [Recraft](https://www.recraft.ai/) | **矢量 SVG 直出**，再栅格化成 32×32 | ⚠️ 免费档产出归平台、**不可商用**，必须付费档 |
| [帧灵 FrameSprite](https://cn.framesprite.com/) | 国内、按积分、动作序列帧、Cocos 教程 | 协议：不主张生成结果所有权、可用于商业项目，但明示权利归属不确定，发布需按平台要求声明 |
| [SpriteFlow](https://spriteflow.io/zh-CN) | 8 向、风格训练、精灵表 + JSON | 风格锁定是其卖点 |

**合格线**：抽 20 个试产，人工可用率 ≥ 60% 才全量；否则退回"矢量图标 + 重着色"。

### 3.2 单位（战略级，先做"三件套"）

| 方案 | 做法 | 适合 | 风险 |
|---|---|---|---|
| **A. 像素模型直出** | PixelLab / SpriteFlow 出 4 向 × 4 态，32×32 | 杂兵、玩家 | 风格漂移，需逐帧修 |
| **B. 云端微调** | [Scenario](https://www.scenario.com/pricing) Pro（$45/月）：10~30 张风格图 / 5~15 张角色图训专属模型 | 24 个单位统一画风 | 需先有"锚定图"；不能拿阻断素材训 |
| **C. 3D 烘焙** | [Hunyuan3D 2.1](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1)（社区许可：EU/UK/KR 除外，100 万 MAU 以上需授权）→ Blender 转台渲染 → 像素化 | BOSS、大立绘 | 32px 下细节糊，不适合杂兵 |
| **D. 视频转序列帧** | Wan2.2（Apache-2.0）或即梦/可灵生成黑底/绿幕 → 抠图 / 加色混合 | 单次动作、特效 | 循环帧不稳，逐帧对齐麻烦 |

**建议**：A 为主、C 只做 BOSS；先做「1 个玩家 + 1 个杂兵 + 1 个 BOSS」，
进 360×640 实机看怪潮里的可读性，再决定是否全量。
（[Sprite Smithy](https://www.spritesmithy.com/)、[Game Sprite AI](https://gamespriteai.com/) 这类"视频→精灵表"工具可作 D 的捷径。）

### 3.3 技能特效（穿插做，成本最低）

1. **首选程序化**：沿用 `battle/Battle.ts` 里 `spawnBolt()` 的 Graphics 画线路线，
   再加 Cocos 3.8 的 `.effect`（[官方着色器文档](https://docs.cocos.com/creator/3.8/manual/zh/shader/)）。
   零贴图、可参数化、按元素改 tint 就能出 10 种变体——这正是视频证明的能力。
2. **次选序列帧**：[Pixel FX Designer](https://codemanu.itch.io/particle-fx-designer)（约 $19.95，像素粒子直出序列帧 / GIF）、
   [EmberGen](https://jangafx.com/software/pricing)（流体/能量，indie 约 $19.99/月 或 $299.99 买断，导出 flipbook）。
3. **只补关键帧**：现有 VFX 库的"循环体"够用，缺的是**起手/命中**的 2~3 帧冲击；
   不要重做整套 16 帧。
4. **元素变体靠参数**，不靠新素材（冰/火/毒 = 同一套序列帧 + 调色 + 叠加）。

## 4. 统一化管线（比选哪个工具更重要）

AI 出 100 张就是 100 种画风。要让它像一个游戏，必须有这一层：

```
任意 AI 图 → 去背景 → 裁边 → 缩到 32/48（Nearest）
          → 固定调色板量化（24 色，从 approved 素材统计）
          → 1px 描边 / 描边色统一
          → 输出 PNG + manifest + 对照页（contact sheet）
```

落地为 `tools/ai2pixel.py`（新增，走 Python + Pillow，不跑本地大模型，符合 rules §3B）：

- 自动写入 `data/UnitFrames.ts` / `IconMap.ts` 的**候选清单**，不直接改生产映射；
- 每次产出一张对照页，VLM **单张**复核（1 图 1 进程，跑完即释放）；
- 量化后像素数、色板命中率用脚本量，不靠肉眼（rules §3B-4）。

## 8. 不要做

1. **不要用主池 / 禁训素材训 LoRA**——上游许可 + 项目红线双重违规。
2. **不要在用户机器上批量跑本地扩散模型**（rules §3B）。
3. **不要用免费档产出做正式资产**（Recraft 免费档归平台）。
4. **不要指望 AI 直出 4 态动画不改**——经验返工率 30~50%。
5. **不要把 3D 直出场景塞进 2D 像素玩法**——风格冲突，只用于宣传/主菜单。
6. **不要为了 AI 改现有的 32×32 / Nearest / 整数倍约束**。

## 10. v2 复核与增补（2026-10-20，本会话实测）

### 10.1 视频复核：抽帧看过的，不是转述

| 项 | 实测 |

| 片尾 | 「前端排行 48 个模型、9926 次对比」，V4.1 Flash 1017 第 **8/48**，胜率 63.5% |

**与 §1 完全一致**，无需改判。唯一补充：视频被测的模型就是本会话正在跑的模型

### 10.3 LoRA 三条路（回答「不限于现有软件」那半句）

| 路线 | 现实成本 | 周期 | 卡在哪 |
|---|---|---|---|
| **A 本机自训**（RTX 4060 8G） | 0 元 | 1~3h/个 | SDXL 官方建议 12G；FLUX LoRA 虽有 4~8G 优化方案，但 rules §3B 明令禁止在本机批量跑扩散模型 → 只能单次、先告知用户 |
| **B 云端训**（fal / Replicate） | **$2.4~10 / 次** | 20~60 min | 要 20~50 张风格图起步 |
| **C SaaS 微调**（Scenario 等） | $45/月 | 半天 | 要「锚定图」 |

**但真正的卡点不是钱，是训练集**：主池 24 单位 534 帧是**禁训素材**（上游禁商用 + 禁 AI 训练，D-26），
拿它训 LoRA = 双重违规。我们目前**没有一套合规的像素训练集**。
→ 结论：**LoRA 现在不做**。等自产像素资产积累到 100+ 张（图标试产就能攒），再用 B 路线锁风格，那时才有意义。
LoRA 解决的是「风格一致」，我们现在的问题是「从 0 到 1 的可商用资产」——顺序不能倒。

### 10.4 价格重算（修正 §6）

| 任务 | 量 | 按 API 单价 | 原 §6 估值 |
|---|---|---|---|
| 129 个图标 | 129 张 | $3~13 | ¥100~300/月 |
| 1 个单位（8 向 × 4 帧） | ≈ 17 次调用 | **≈ $0.38** | ¥20~60 |
| 24 个单位 | 534 帧 | **≈ $9** | ¥500~1,500 |

**钱不是瓶颈，返工工时才是**（AI 直出 4 态仍要 30~50% 返工）。
原估值把「订阅费 + 人工」混算了；单看生成费低一个数量级。这也意味着：**可以小额试错，不必先立项。**

### 10.5 结论修订

1. **排序不变**：程序化特效（0 成本）→ 图标（快赢）→ 单位（战略）；**LoRA 排最后**。
2. §7 的「M28 候选」已过期（M28/M29 被用户反馈占用）→ 三个实验改为「可随时插入」，编号 A/B/C 保留。
3. **新增一条**：图标试产时先跑 PixelLab 的 correct-pixelart / unzoom / reduce-colors 三个 Pro Tools，
   比自己写量化脚本更快验证「AI 图能不能变成干净的 32×32」——过了这关再投入写 tools/ai2pixel.py。
