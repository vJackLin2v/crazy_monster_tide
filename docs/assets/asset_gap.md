## 3. 解决方案优先级（需求 §8）

```
已有素材改造 → 网络合法素材 → AI 生成 / 改造 → 占位
```

| 缺口 | 建议路径 | 备注 |
|---|---|---|
| GAP-101/102 | **网络合法素材（CC0）优先** | 母本已核实 Kenney 全系列 / 32rogues / SunnyLand / DCSS 为 CC0 或可商用；这是**最低成本且零授权风险**的路 |
| GAP-103 | Kenney 面板重着色 + 程序自绘 | 不碰被阻断的 `ui/kit` |
| GAP-104 | Kenney CC0 音频包 | 首版可先静音，但需登记 |

### 为什么不建议直接「AI 生成」

1. 母本池中 **GandalfHardcore 明文禁止 AI 训练**，链条上容易踩坑；
2. AI 生成物的**版权归属在平台审核时仍有不确定性**；
3. 像素风 32x32 的一致性（同一套角色四态）AI 很难稳定产出。

> 结论：**先找 CC0 包，找不到再自绘，最后才考虑 AI**。

## 4. 占位素材纪律

- 进入占位必须在**本文件**登记，写明替换条件；
- 占位不得进入最终验收包；
- 不得因为「看起来还行」就永久保留。

**当前占位清单**：原型阶段的单位与特效是**程序几何体**（`prototype-html/` 的字符画精灵），
不是占位素材，属于「程序绘制」——可保留，但正式美术接入后应替换为规范像素素材。
