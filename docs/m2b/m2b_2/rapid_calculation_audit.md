# rapid 冷却缩减计算与文案审查

> 审查基线：HEAD `26bfe64`（main，工作区无未提交源码修改；仅有未跟踪的提示词文件）。  
> 本轮只读审查，未修改任何游戏源码/数值。

## 1. 源码路径与函数

| 作用 | 文件 / 函数 |
|---|---|
| rapid 模块定义 | `cocos/assets/scripts/data/Modules.ts` `MODULES.rapid`（`stack:'tier'`、`max:3`、`requires:['projectile','pulse','chain','area']`） |
| 模块等级效果份数 | `Modules.ts` `levelOf` / `modEffect`（`1 + 0.6 × (level-1)`：Ⅰ=1、Ⅱ=1.6、Ⅲ=2.2） |
| 法师职业修正 | `data/Chars.ts` mage `stats.modCdrMul = 1.25` |
| 实际冷却计算 | `game/SkillCalc.ts` `calcSkill`：`rapidPer = stats.modCdrMul ? 0.88^stats.modCdrMul : 0.88; cd *= rapidPer^rapid` |
| 单模块数值文案 | `game/ModuleText.ts` `moduleDetailText`：`1 - 0.88^e`，未使用 `modCdrMul` |
| 升级卡数值文案 | `GameRoot.ts` `toCard`：`nums: MODULE_NUMS[r.id] ?? ''`；`Modules.ts` `MODULE_NUMS.rapid = '冷却 -12%'` |
| 安装/商店/Build 面板文案 | `GameRoot.ts` 951（安装）、1215（商店）、1549（技能详情）、1578/1588（黑科技列表）均调用 `moduleDetailText` |

## 2. 完整执行链路

```
rapid 模块 id（rapid / rapid_2 / rapid_3）
→ levelOf(id) → modEffect(id)=e
→ SkillCalc: rapid += e（可叠多个 rapid 模块）
→ rapidPer = modCdrMul ? 0.88^modCdrMul : 0.88
→ cd *= rapidPer^rapid
→ 其他冷却乘区（急速、标签 cd、cdr、下限）
→ 最终技能 cd
```

UI 链路：

- `moduleDetailText(id)` → `1 - 0.88^e`（**没有 stats 参数**，不知道角色）；
- `MODULE_NUMS.rapid` → 固定 `冷却 -12%`（升级卡基础模块）；
- 合并等级（rapid_2/rapid_3）在 `MODULE_NUMS` 中没有键，升级卡路径不会显示数值（奖励池只抽基础模块，因此主要影响详情/商店/Build 路径）。

## 3. 逐级计算

公式（仅 rapid 乘区，未计技能等级、急速、cdr 和总冷却下限）：

```
最终冷却倍率 = rapidPer ^ rapid
rapidPer     = 0.88（普通）/ 0.88^1.25（法师）
冷却缩减     = (1 - 最终冷却倍率) × 100%
```

### 普通角色（modCdrMul 未设置）

| 等级 | e | rapidPer | 倍率 | 实际缩减 | `moduleDetailText` | 升级卡 `MODULE_NUMS` |
|---|---:|---:|---:|---:|---|---|
| Lv.1 | 1 | 0.88 | 0.88^1 = 0.880000 | 12.0000% → 12.0% | 冷却 -12.0% | 冷却 -12% |
| Lv.2 | 1.6 | 0.88 | 0.88^1.6 = 0.815027524 | 18.4972% → 18.5% | Lv.2 · 冷却 -18.5% | 奖励池只出基础模块，实际不出现 rapid_2 |
| Lv.3 | 2.2 | 0.88 | 0.88^2.2 = 0.754852119 | 24.5148% → 24.5% | Lv.3 · 冷却 -24.5% | 同上 |

### 法师（modCdrMul = 1.25）

| 等级 | e | 有效指数 1.25×e | 倍率 | 实际缩减 | `moduleDetailText` | 升级卡 `MODULE_NUMS` |
|---|---:|---:|---:|---:|---|---|
| Lv.1 | 1 | 1.25 | 0.88^1.25 = 0.852321297 | 14.7679% → 14.8% | 冷却 -12.0% | 冷却 -12% |
| Lv.2 | 1.6 | 2.00 | 0.88^2 = 0.774400000 | 22.5600% → 22.6% | Lv.2 · 冷却 -18.5% | 无 rapid_2 条目 |
| Lv.3 | 2.2 | 2.75 | 0.88^2.75 = 0.703602459 | 29.6398% → 29.6% | Lv.3 · 冷却 -24.5% | 无 rapid_3 条目 |

**示例**：法师 rapid Lv.2，火球基础 cd 0.85s；仅 rapid 乘区后为 `0.85 × 0.7744 = 0.6582s`（实际还会再乘急速/标签/cdr，并受总冷却下限）。普通角色同条件为 `0.85 × 0.8150 = 0.6928s`。

## 4. UI 文案与实际对照

| 场景 | 实际值（普通） | UI | 实际值（法师） | UI |
|---|---:|---|---:|---|
| rapid Lv.1 | 12.0% | 12.0% / 升级卡 -12% | 14.8% | **12.0% / -12%（错误）** |
| rapid Lv.2 | 18.5% | 18.5% | 22.6% | **18.5%（错误）** |
| rapid Lv.3 | 24.5% | 24.5% | 29.6% | **24.5%（错误）** |

结论：**普通角色文案正确；法师所有 rapid 等级均低报约 2.8~5.1 个百分点**（Lv.1 -2.8pp、Lv.2 -4.1pp、Lv.3 -5.1pp）。

## 5. 额外发现：注释与实现不完全一致

`SkillCalc.ts` 125-127 行注释写：

> “0.88 的‘效果’是 -12%，×1.25 → -15% → 单份系数 0.85”

但实现是 `0.88^1.25 = 0.852321`，不是 `0.85`；Lv.1 实际 14.77%，不是 15.00%。

- 如果设计意图是“**减免幅度** ×1.25”（12%×1.25=15%），实现存在约 0.23pp 的偏差；
- 如果设计意图是“**冷却乘区指数** ×1.25”，实现正确，注释写 0.85 只是近似；
- 无论哪种，**UI 的法师文案都错误**，因为它完全没乘职业修正。

本轮不判断该公式必须改；这需要设计 owner 确认“×1.25”的语义。仅凭注释不能认定战斗数值错误。

## 6. 最终结论

**B. 文案错误，但战斗实际数值按当前代码正确，只需要修正文案。**

- 错误位置：`game/ModuleText.ts` rapid 分支；`data/Modules.ts` `MODULE_NUMS.rapid`（升级卡）。
- 影响角色：法师（`modCdrMul=1.25`）；普通角色不受影响。
- 影响等级：法师 rapid Lv.1/2/3 全部低报。
- 是否只影响显示：**是**；本轮未发现 `calcSkill` 在 rapid 乘区上的执行错误。
- 是否影响战斗：否（按当前代码）；若设计确认“×1.25 是减免幅度”，则公式需另行评审，不应在本轮直接改。
- 是否影响其他职业修正：`modCdrMul` 当前只用于 rapid，未发现其他属性/模块读取。

## 7. 建议

- **P1/P2**：给 `moduleDetailText` 传入当前 `CharStats`（或显式的基础值 + 职业修正说明），使法师显示 14.8/22.6/29.6；升级卡对基础 rapid 也要用同一逻辑。
- 同时修正 `SkillCalc` 注释或由设计确认语义；不要在未确认前改公式。
- 验收：普通/法师 × Lv.1/2/3 六组文案与 `calcSkill` 实际缩减一致（允许 0.1pp 展示误差）。
