# 测试协议

## 1. 分层

| 层 | 目标 | 工具 | 何时必须跑 |
|---|---|---|---|
| L1 单元 | 纯逻辑：伤害 / 模块叠加 / 奖励抽取 / 地图生成 | 语言原生测试框架 | 每次改动逻辑 |
| L2 集成 | 系统间协作：技能 x 模块 x 道具 x 标签 | 同上 | 改动联动规则 |
| L3 场景 / E2E | 玩家真实流程：选人 → 地图 → 战斗 → 升级 → 结算 | Playwright（原型阶段） | 每个里程碑 |
| L4 视觉 | 布局 / 可读性 / 像素对齐 / 三档视口 | 截图 + 人工确认 | UI 改动 |
| L5 性能 | 怪潮峰值帧率、对象数量上限 | 引擎 Profiler | 战斗系统改动 |

## 2. 硬性要求 `[定]`

1. **不能只有脚本测试**：必须有玩家流程测试与视觉检查。
2. 核心玩法随机**必须由统一 RNG / Seed 驱动**。
3. 测试失败必须保留：**seed / game state / 截图 / trace / 复现步骤**。
4. 修复后必须**回归**，并说明是否影响既有功能。
5. 视觉确认的结论必须落盘（写清截图路径与结论）。

## 3. 完成口径

一个任务只有在 `实现完成 + 单元/集成测试通过 + 至少一条玩家场景通过 + 必要视觉检查通过
+ 无未记录的素材缺口 + 状态文件已更新` 时，才算完成。
