# UI 能力协议（**做任何 UI 前必读**）

> 本协议管的是「**UI 怎么做**」，不改「游戏怎么做」。
> 复杂 UI **不允许凭感觉设计**，也不允许在正式引擎里反复试。

## 1. 触发条件 → 该读什么

| 你要做的事 | 必须先读 | 目的 |
|---|---|---|
| 任何 UI 任务 | 本文件 | 拿到强制流程 |
| 设计新页面 | `docs/ui/screen_specs.md` + 本文件 §2 | 先套规格，别从零想 |
| 定颜色 / 字号 / 间距 / 触控 | `docs/ui/screen_specs.md` | 统一 token，不许各页一套 |
| 判断原型能否过门禁 | `docs/ui/prototype_gate.md` | 体验门槛清单 |
| 页面写完要自评 | `docs/ui/prototype_gate.md` §3 | Critic 清单（含像素 / 微信硬项） |
| 多尺寸验证 | `docs/ui/screen_specs.md` §4 | 375x812 / 390x844 / 412x915 |
| 冻结 UI 交给引擎实现 | 本文件 §3 | 冻结前置条件 |

## 2. 复杂 UI 强制流程（不允许跳步）

```
需求分析
 → 参考检索（>=3 个优秀案例，同品类优先）
 → 参考分析（结构化：布局 / 信息层级 / 交互 / 为什么有效）
 → Pattern 提取（沉淀可复用布局）
 → Design Token 应用（颜色 / 字号 / 间距 / 热区统一）
 → HTML 可玩原型（必须可玩，不是视觉稿）
 → Playwright 真实视口测试
 → 截图
 → UI Critic 自评（过清单）
 → 修改
 → UI Freeze（产出 ui-spec-approved）
 → 引擎实现（只实现，不得重新发明布局）
```

## 3. 冻结（Freeze）前置条件

必须全部满足才能冻结：

1. 原型**可玩**，核心循环完整可跑通；
2. 三个竖屏视口验证通过，无溢出 / 无遮挡 / 热区不重叠；
3. Critic 清单全过；
4. 截图存档；
5. 产出 `docs/ui/ui-spec-approved.md`，明确：尺寸 / 层级 / 交互 / 状态 / 文案；
6. **用户确认**。冻结后不得私自改布局。

## 4. 四条硬边界

1. **参考案例 != 游戏素材**：第三方截图 / 图标 / 字体默认只做参考，**不得**进入正式素材路径。
2. **不许「找到一个案例就照抄」**：至少分析 3 个，提取规律后按本作需求设计。
3. **正式素材一律走 Asset Gate**（`docs/assets/asset_license.md`）。
4. **已实现的 UI 不推倒重来**：只在后续任务涉及该页面时逐步改善。
