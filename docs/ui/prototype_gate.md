# HTML 原型门禁（S2 通过标准）

## 1. 硬性要求

**HTML 原型必须是「可玩的」，不是静态视觉稿。** 至少能完整跑通：

```
选角色 → 进入地图 → 选节点 → 战斗（走位 + 自动攻击 + 怪潮 + 升级）
→ 升级 3 选 1 → 行为模块安装 → 继续推进 → 商店 / 事件 → Boss → 结算
```

## 2. 门禁清单

- [ ] 核心循环完整：能从头玩到结算，不是只有单屏演示
- [ ] 动态摇杆可拖动，松开消失，边界不越界
- [ ] 4 技能自动开火，怪潮生成与清理有可见反馈
- [ ] 升级 3 选 1 出现，4 类奖励至少各有 1 个可用样本
- [ ] 行为模块能装到兼容槽位，能卸下 / 搬家
- [ ] Build 面板能查看技能 / 模块 / 道具 / 属性
- [ ] 地图节点可选择，节点状态可辨
- [ ] 战斗 HUD 与需求 §4 一致（顶部信息 + 4 技能状态栏）
- [ ] 三档竖屏视口无布局事故
- [ ] 固定 Seed 可复现同一局
- [ ] Playwright 玩家流程 E2E 至少 1 条全绿 + 截图存档

## 3. Critic 自评清单（写完必过一遍）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 信息层级 | 战斗中一眼能看出 HP / 经验 / 技能状态 |
| 2 | 可读性 | 怪潮最密时，玩家角色与伤害数字仍可辨 |
| 3 | 拇指区 | 主要交互全在单手可达范围 |
| 4 | 反馈 | 每次操作都有可见反馈 |
| 5 | 像素规范 | 无模糊缩放、无非整数倍拉伸 |
| 6 | 状态完备 | 空态 / 满态 / 不可点 / 冷却均有表现 |
| 7 | 文案 | 无错别字，术语与 `docs/systems/*` 一致 |
| 8 | 合规 | 无赌博语义元素 |

## 4. 不通过时

记录问题 → 修改 → 重跑清单 → **不要在未过的前提下进入引擎实现**。
