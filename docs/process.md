# 开发流程与阶段门禁

## 1. 阶段门禁（顺序不可跳）

```
S0 需求分析           交付：requirements 固化 + 待决策项登记
S1 素材评估门禁       交付：asset_requirements / inventory / gap / license / normalization
S2 HTML 可玩 MVP      交付：可玩原型（核心循环完整，不是视觉稿）+ 玩家流程 E2E
S3 UI 迭代与规格冻结  交付：ui-spec-approved（尺寸 / 层级 / 交互冻结）
S4 正式引擎实现       交付：按 UI Spec 实现，不重新发明布局
S5 自动化测试 → S6 玩家模拟 → S7 视觉回归 → S8 综合验收
```

**未通过当前阶段门禁，不得进入下一阶段。** 特别地：S2 未确认前不写 S4 的代码。

---

## 2. 单任务工作流

```
Research → Innovate → Plan → Execute → Review
```

- 未经对应阶段确认，不得跳阶段。
- Execute 内部分工：`Scout`（摸清现状）→ `Builder`（写）→ `Verifier`（验）。
- **同一任务默认只允许一个 Builder 改代码**（避免并发覆盖与风格分裂）。

---

## 3. 里程碑制（用户强制）

一次只做一个里程碑：

```
开工前说明范围 / 文件 / 验收标准 → 开发 → 自验贴证据 → 固定格式汇报 → 停下等用户确认
```

禁止：顺手做后面的事、未汇报就继续、多个里程碑合并汇报、无证据报完成。

---

## 4. 任务生命周期

```
tasks.md 登记 → 读需求与规则 → 设计最小方案 → 实现 → 自验（测试 / 冒烟 / 截图）
→ 用户确认 → 更新 tasks.md（必要时同步 decisions.md / architecture.md）
```

未登记的任务不开工；未更新的状态视为未完成。
