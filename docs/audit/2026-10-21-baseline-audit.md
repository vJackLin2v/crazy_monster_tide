## 0. 必须首先澄清的一件事（P0）

**上一轮结算截图的数据矛盾（通关 / 6.3s / 137 杀 / 第 8 波 / 320 金币）来自我自己的测试夹具，不是游戏 bug。**

证据：`GameRoot.showResult(win)` 直接读取当前 `RunState`；那张图是我用脚本
`rs.kills=137; rs.wave=8; showResult(true)` 人为拼出来的，工具人没有走真实的 20 波流程。

真实链路（代码依据）：

| 项 | 代码位置 | 结论 |
|---|---|---|
| 通关触发 | `Battle.advanceWave()`：`next > RUN.waves` 才 `onClear` | 只有打完第 20 波才通关，逻辑正确 |
| 失败触发 | `updateEnemies` 玩家 hp ≤ 0 → `onDead` | 与通关互斥 |
| 结算字段来源 | `GameRoot.showResult`：`rs.wave / rs.lv / rs.kills / rs.runTime / rs.gold` | 同一次 `RunState`，无跨局混用 |
| 时长 | `Battle` 每帧 `rs.runTime += dtRaw` | 实测 0.8s→5.35s 与墙钟一致 |
| 重开 | `startBattle()` 新建 `RunState` | 实测第二局金币/波次从 0 开始 |

**实测数据（真机式 E2E，release 包）**

```
t=0.8s  {gold:1, kills:1, wave:1, runTime:0.80}
t=2.0s  {gold:3, kills:3, wave:1, runTime:2.32}
t=4.0s  {gold:6, kills:6, wave:1, runTime:3.83}
t=8.0s  {gold:8, kills:8, wave:1, runTime:5.35}
```
金币 = 击杀数、时长 = 真实秒数、波次不变（第 1 波未结束）——**数据一致**。

**仍建议加的防呆（P1，小而稳）**
1. `showResult(true)` 时若 `rs.wave < RUN.waves` 打一条 warn（仅开发期），防止将来真的误触发；
2. 结算页把「胜利」与「波次」绑定展示：胜利显示 `20/20 波全部完成`，失败显示 `推进到 第 N / 20 波`；
3. 调试夹具与真实数据隔离：给 `showResult` 增加 `debug` 参数或独立入口，避免截图/测试直接改战斗状态。

**随机种子**：`seed` 是本局的**确定性对局种子**（M47 引入，同种子同奖励/同商店），当前在菜单与结算页都以
`seed 4277487803` 直接展示。建议：普通玩家侧改为「本局种子 · 点击可复制」的小字入口，或仅在暂停/结算页
的次级区域显示；不要在主菜单第一屏用裸数字干扰视线。

## 1. 已确认问题（有截图 + 代码依据）

### P1-1 升级三选一：信息量不足、卡片留白过大
- 证据：`screenshots/audit/battle-7-levelup.png`、`截图包 05_升级三选一`
- 现象：卡片上部名称、下部一句话，中间约 40% 空白；描述如「出手明显更快」「技能转得更快。永久生效，可叠加」无具体数值、无当前叠加层数、无上限提示。
- 代码：`buildLevelUp` 只渲染 `title/sub`；`Reward` 已带 `kind/id`，数值可从 `calcSkill/Attrs/Items` 派生（项目已有 `itemNumbers()` 可复用）。
- 影响：玩家无法判断收益，只能凭颜色选；与「构筑向肉鸽」的核心体验冲突。
- 建议：卡片三段式（效果一句话 / 具体数值 / 叠加状态与上限），复用 `itemNumbers()`；空白区用于数值与标签。
- 验收：所有升级卡都显示真实数值；长描述不截断、不压按钮；三档手机视口不溢出。

### P1-2 商店描述被截断
- 证据：`08_商店`（黑科技「传染」显示为「命中后跳到附近另一只身上（不…」）
- 代码：`buildShop` 用 `fit(s.sub, 15)` 硬截断 15 字。
- 影响：规则信息丢失（这条正好是"不穿透"的关键说明）。
- 建议：两行换行或点击行内展开详情；关键规则（消歧）优先保留。

### P1-3 技能替换页缺少"黑科技如何处置"的说明
- 证据：`06_技能替换`——每行写着「已装 2 个黑科技」，但没有说明换掉后这些模块去哪。
- 待查代码：`RunState.replaceSkill` / `GameRoot.showReplace`（需确认模块是丢弃、回包、还是转移）。
- 建议：按**真实规则**补一行后果说明；若会丢失，需二次确认。

### P1-4 黑科技安装页状态区分弱
- 证据：`07_黑科技安装`——空槽（+）、已装（穿透/上火）、选中项（加量高亮）三者靠颜色区分；
  点击已占用槽位前没有"将被替换"的预览。
- 建议：选中态加描边 + 槽位提示「点击替换：穿透 → 加量」；不可用槽位降到 40% 亮度并禁用点击。

### P1-5 构建面板属性页信息过载
- 证据：`12_构建面板_属性`——24 项全列，其中 12 项为 `+0%`。
- 建议：默认只显示「本局有变化的」+ 核心战斗属性，底部「查看全部」展开；不要删数据。

### P1-6 精英/首领辨识度不足
- 证据：`screenshots/audit/battle-4-elite.png`、`battle-5-boss.png`——精英与普通哥布林体型接近，
  绿色泛光在混战中几乎看不出；BOSS 与怪群混在一起，仅靠顶部血条提示。
- 建议：精英加深绿色描边/地面光圈（不是只靠泛光）；BOSS 增加入场提示与更大的轮廓差异。

#### B. 升级三选一候选分布（rollRewards 连续抽样）
