# 给 GPT 的审核提示词

你是资深游戏设计 + 前端工程评审。下面是一个**微信小游戏**项目的交付材料，请按指定维度审核并给出可执行的修改建议。

## 项目背景

- 名称：《疯狂鸽王》（Crazy Pigeon King）
- 引擎：Cocos Creator 3.8.6 + TypeScript
- 平台：微信小游戏，**竖屏 360×640**，固定宽度适配
- 类型：像素风 · 自动攻击割草 · 构筑向 Roguelite
- 核心循环：20 波怪物 → 每波结束进商店 → 升级三选一 → 4 技能 × 每技能 3 个黑科技槽 → 成型后清场 → 结算（可继续无尽）

## 你手上的材料

1. `README.md` —— 项目状态总结（功能清单、数值现状、代码结构、已知问题）
2. `CHARS.md` / `SKILLS.md` / `MODULES.md` / `ITEMS.md` —— 角色、技能、黑科技、道具全量数据表
3. `data_snapshot.json` —— 同上数据的机器可读快照
4. `screenshots/01~17.png` —— 全部页面截图（360×640，2 倍图）

## 请按这 6 个维度输出

1. **信息架构与布局**：每个页面的信息优先级是否合理？360×640 下有没有拥挤/空洞/对齐问题？截图里能否指出具体的像素级问题（给出估算坐标）？
2. **可读性**：字号（正文 11px、说明 10px、按钮 12~16px）、对比度、长文本截断策略是否足够？哪些文案应该改写得更短？
3. **交互与反馈**：点击热区（≥44px）、禁用态、二次确认、滚动（拖动/惯性/边界）是否有缺失或不一致？
4. **数值与节奏**：根据 SKILLS/MODULES/ITEMS 表格判断——是否存在明显的最优解/无效选项？成长曲线（HP +18%/波、伤害 +10%/波、刷怪 8.82/s 峰值）在第 5/10/15/20 波是否会出现“突然打不动”或“毫无压力”？给出具体参数建议。
5. **构筑深度**：4 技能 × 3 槽 + 70 道具 + 18 黑科技的组合空间是否足够？哪些组合会导致数值崩坏（请点名具体 id）？
6. **工程与可维护性**：基于 README 的代码结构与已知问题，指出三个最高风险的工程债，并给出优先级排序。

## 输出格式要求

- 用中文，Markdown；
- 每个维度先给**结论一句话**，再列 3~6 条**具体问题 + 修改建议**（能落到数值/坐标/文案的尽量给具体值）；
- 最后给一个「**如果只改 3 件事，改哪 3 件**」的清单，按收益/成本排序；
- 不要泛泛而谈“建议优化体验”，每条建议必须可执行、可验证。
