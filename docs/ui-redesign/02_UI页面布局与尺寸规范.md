# UI 页面布局与尺寸规范

版本：1.0  
项目：《像素共鸣：远征》  
设计基准：横屏 1280×720；该尺寸只是布局参考画布，不代表所有手机的物理分辨率。

> 随包附带的 `04_UI布局线框参考.html` 可离线打开，切换查看 9 个页面的布局示意。线框不是最终视觉资产；开发时必须用实际像素 UI 素材、可编辑文本和真实游戏数据替换示意矩形。

## 1. 总体规范

### 1.1 横屏与安全区

- 参考画布：1280×720，16:9。
- UI 安全边距：主要信息距离安全区域边界至少 24–32 设计像素。
- 关键按钮：建议可触控区域至少约 56×56 设计像素；主要 CTA 高度约 56–64。
- 页面标题：32–40 设计像素；区块标题：20–26；正文：18–22；辅助信息不低于约 14–16。实际字号应在设备截图中校准。
- 上述为设计稿尺寸，不应作为所有设备的固定屏幕绝对坐标。必须用当前 Cocos 工程的 Canvas、UITransform、Widget、设计分辨率及安全区域适配方案实现。
- 对非 16:9 比例，应优先保留中央核心布局，通过扩展背景或调整外侧区域适配，不能拉伸整个 UI。
- 微信小游戏没有鼠标悬停作为主要交互；按钮必须有按下/选中状态。

### 1.2 视觉语言

- 使用传统像素游戏 UI：边缘清晰、像素比例一致、按钮状态明确。
- 主面板建议用深蓝灰/深色中性色，文字用高对比浅色。青/蓝代表选择/当前状态；金色用于稀有/重要强调；绿色用于生命或正向状态；蓝紫用于经验/奥术；红色用于危险/受伤。
- 具体主色需对所选 UI 包的实际素材进行取样后再定，不可把不同 UI 包的边框无规则混搭。
- 同类控件必须统一边框、内边距、标题栏、字体和状态：按钮、面板、卡片、角标和状态条不得每页各用一套。
- 图像过滤优先最近邻；像素图片尽量整数倍缩放。面板应优先使用九宫格或切片，不得拉伸四角。
- UI 不要抢过战斗特效的注意力；战斗状态下常驻 UI 以高可读、低遮挡为原则。

把信息清晰地放在画面边缘，中间留出主要战斗区；能看见角色、怪群和技能特效。

### 参考坐标与区域

| 区域 | 参考坐标 x,y,w,h | 说明 |
|---|---:|---|
| 左上玩家状态 | 24,20,300,100 | 生命条、等级、经验条；只放必要数值 |
| 上方关卡信息 | 340,22,220,48 | 当前关卡/计时等，避免重复显示 |
| Boss 血条 | 410,20,460,58 | 仅 Boss/精英战斗时展示；无 Boss 时隐藏 |
| 右上暂停 | 1192,20,64,64 | 清楚的暂停按钮，考虑安全区域 |
| 左下摇杆 | 42,560,138,138 | 只有当前游戏实际使用摇杆时显示 |
| 右下技能栏 | 944,612,300,72 | 4 个技能槽，每格建议 64–68；间距约 8–12 |
| 底部资源/状态 | 300,656,500,36 | 仅展示对玩家有用的数据，必要时可不显示 |

### 线框

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ [HP  ███████   LV] [XP █████████]     [BOSS / ELITE  HP █████████]    [Ⅱ] │
```

实现要求：
- 不能为了漂亮把战斗区域缩成小窗口。UI 只覆盖边缘必要位置。
- 四个技能槽必须对应现有四个主动技能，不得展示虚构技能。
- 图标使用已有技能图标；如果没有，可从现有特效中选择清楚的一帧作为缩略图，不要把整个动画播放区域压缩进图标槽。
- 冷却、层数、等级、状态等只在业务数据存在时显示。
- Boss 血条在非 Boss 场景中应隐藏，不保留假的默认血量。
- UI 动画需节制，不能持续发光闪烁干扰辨识。

## 6. 页面 5：暂停与设置

### 暂停弹窗布局

- 背景覆盖层：全屏暗化，建议保留约 35–50% 的底层可见程度；具体以游戏画面判断。
- 主窗口参考尺寸：460×430，居中（约 x=410,y=145）。
- 标题栏高约 60。
- 纵向按钮：继续游戏、设置、返回主菜单；只显示当前已有功能。
- 每个按钮高 52–60，间距 12–16。
- 点击弹窗以外区域是否关闭按现有操作规范决定，不要擅自改变暂停行为。

```text
             ┌─────────────────────────────┐

             │  ┌───────────────────────┐  │
             │  │       继续游戏          │  │
             │  └───────────────────────┘  │
             │  ┌───────────────────────┐  │
             │  │         设置            │  │
             │  └───────────────────────┘  │
             │  ┌───────────────────────┐  │
             │  │      返回主菜单         │  │
             │  └───────────────────────┘  │
             └─────────────────────────────┘
```

设置页面采用左侧分类（如果存在多个分类）+ 右侧选项的结构；没有必要时用单列即可。只展示已实现的设置，控件必须真实可操作。

## 10. 页面 9：成长档案/图鉴（仅项目已有该系统时）

- 左侧固定导航约 190–220 宽：角色、技能、怪物、道具等真实分类。
- 中间内容区约 650 宽：统一卡片网格和滚动区域。
- 右侧详情区约 300–340 宽：选中项预览、名称、说明和解锁状态。

- 只显示当前项目真实存在的数据。

## 11. 通用 UI 组件规范

至少建立可复用的：

- `Window/Panel`：外框、标题栏、内容区，支持九宫格/切片。
- `Button`：普通、主按钮、危险、禁用、按下、选中状态。
- `ProgressBar`：生命、经验、Boss 血量等通过配置颜色区分，不要重复造控件。
- `Card`：角色、技能、道具共用基础布局，使用变体而不是完全不同的样式。
- `IconSlot`：统一图标尺寸、边框、角标。
- `Modal`：统一暂停、确认和提示弹窗。
- `Currency/Counter`：货币、数量和资源展示。

组件要符合当前项目的 Cocos 版本和已有代码习惯，不要为了组件化引入大型新依赖。

## 12. 页面检查标准

每个实际页面都要检查：

- 不溢出、不重叠，四边不被裁掉。
- 中文文字清楚、长度变化可承受。
- 像素边缘清楚、面板切片不变形。
- 按钮触控区域够大、选中和按下反馈明显。
- 弹窗层级正确，弹窗打开时底层不会误触。
- 页面切换、返回、暂停和恢复保持当前游戏行为。
- 在实际 Cocos 运行画面检查，不能只看线框 HTML。
