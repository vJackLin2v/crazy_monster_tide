# UI 页面实现说明（v2 · 像素共鸣专项改造）

> 项目：《疯狂怪潮》（crazy_monster_tide，Cocos Creator 3.8.6）　｜　日期：2026-10-28
> 上游规格：`docs/ui-redesign/02_UI页面布局与尺寸规范.md`（1280×720 横屏参考稿）
> 本文记录**实际工程里的落地结果**：每一页的区域、尺寸、绑定数据、交互入口、适配方式。

## 0. 先说明一个必须处理的冲突（重要）

上游规格按 **1280×720 横屏**给出参考坐标，但它描述的游戏（横屏俯视角）与本工程**不是同一个**：

| 项 | 规格文档假设 | 本工程实际 | 处理 |
|---|---|---|---|
| 项目名 | 《像素共鸣：远征》 | 《疯狂怪潮》（包名 `crazy_monster_tide`） | 以**实际工程**为准 |
| 屏幕 | 横屏 1280×720 | **竖屏 360×640**（`FIXED_WIDTH`，见 `docs/ui/screen_specs.md`） | **保留竖屏**，把横屏的"区域关系"重排成竖屏 |
| 页面 | 9 页，含路线 / 图鉴 / 转职 | 11 个已实现界面（无路线、无图鉴、无转职） | **不虚构**，只改已有页面 |
| 技能槽 | 4 个 | 4 个（一致） | — |

**裁决依据**：任务书自己写的最高优先原则是"保护当前游戏功能、先检查实际项目、只改 UI、不虚构功能"，
并且"坐标是参考值，必须按当前工程的设计分辨率正确映射"。
因此本次**没有**把游戏改成横屏，也没有新增路线/图鉴/转职，而是：

- 保留 360×640 竖屏 + `FIXED_WIDTH` 适配；
- 把横屏规格里的**结构意图**（HUD 贴边、中央留空、三张等卡、左列表+中预览+右详情、商店网格+详情）
  按竖屏可用宽度重排为：HUD 贴上下边、三选一改为**三张纵排**、角色选择保持 **3×2 网格 + 下方详情**、
  商店为 **4 行货架 + 底部已有道具**；
- 所有尺寸以设计像素给出，实际位置用 `view.getVisibleSize()` 换算（不写死 640）。

## 2. 通用组件（全部在 cocos/assets/scripts/ui/）

| 组件 | 文件 | 说明 |
|---|---|---|
| panel(parent,x,y,w,h,{art}) | UIKit.ts | 九宫格面板；art 指定 panel / panel_soft / well / slot / card_sel / card_gold / rim_* |
| paintPanel(n,w,h,{art}) | UIKit.ts | 运行时换底（选中/稀有/禁用），只换 spriteFrame 不重建节点 |
| button(x,y,w,h,text,{primary/danger/disabled}) | UIKit.ts | 九宫格按钮 + **按下换图 + 文字下沉**；热区强制 ≥44 |
| slot(x,y,size,{empty}) | UIKit.ts | 图标槽（slot / well），四角不拉伸 |
| chip(x,y,text,{color}) | UIKit.ts | 小标签（类别、价格、持有数）；小尺寸用 2px 黑边方框，和素材线宽一致 |
| gradBar(...,{from,to}) | UIKit.ts | 像素血条：底槽 + 主色块 + **顶部 2px 高光**（不再是渐变） |
| screenHeader(parent,vw,top,title,h,sub) | UIKit.ts | 统一标题条（商店/结算/角色选择共用） |
| text / title | UIKit.ts | 文本原语（描边 / 硬投影 / 多行高度） |
| mask(w,h) | UIKit.ts | 暗化层 + **BlockInputEvents**（防弹窗下层误触） |
| uiFrame / setUiSprite | Art.ts | 九宫格素材登记与挂载（缺素材自动回退 Graphics） |
| Assets.loadUi() | engine/Assets.ts | 载入 52×52 PNG，强制 NEAREST + 设 10px 九宫格边距 |
| safeTop() / safeBottom() | Safe.ts | 安全区（刘海 / 手势条），优先读宿主 getSafeAreaRect() |

## 3. 逐页说明（数据绑定 + 交互 + 适配）

### 3.1 主菜单 buildMenu
- **区域**：全屏背景（home-bg-360x640，cover 缩放）→ 标题（S+74 / 44px + 副标题 12px）→ 主 CTA 268×58（S+300）→ 次按钮 268×52（S+372）→ 页脚（离底 48/65，10px 灰字）。
- **绑定数据**：本局种子、四项玩法要点文案。
- **交互**：开始游戏 → showCharSelect()；玩法说明 → showHowto()。
- **适配**：标题/CTA 按安全区下移；页脚按底部安全区上移；背景 cover（非拉伸）。

### 3.2 玩法说明 buildHowto
- **区域**：标题条（54 高）→ 4 步卡片面板（336 宽，每步 56 高）→ 提示一行 → 底部返回。
- **绑定数据**：4 条固定规则文案。
- **交互**：返回 → 主菜单。

### 3.3 角色选择 buildCharSelect
- **区域**：标题条（62 高，含副标题）→ 3×2 角色卡（106.67×124，来自 CharLayout.CS）→ 详情面板（顶边跟网格、高度按内容）→ 底部 返回(96) + 开始闯关(232)。
- **绑定数据**：CHARS 6 个（名字、正/负天赋、初始技能与图标、stats：攻击/移速/生命/暴击/回血/拾取、立绘 portrait 去透明边后整数倍放大）。
- **交互**：点卡片 = 选中（**青色描边 + 提亮底**，不只改文字色）；翻页按钮（角色 >6 才出现）；开始闯关 → 进战斗。
- **适配**：detailBox(VH - GRID_DY - B)，矮屏自动切紧凑排版。

### 3.4 战斗 HUD（Hud.ts，最高优先级）
- **区域**（设计坐标，原点左上；顶部另加安全区 S）：

| 元素 | 位置 |
|---|---|
| HP 条 156×18 | (10, S+2) |
| 经验条 156×14（LV 嵌右端） | (10, S+22) |
| 金币图标 16 + 数字 | (18, S+48) |
| 波次 · 击杀（右对齐 350） | y = S+8 |
| 倒计时 24px（右对齐 350） | y = S+32 |
| 暂停 34×34（热区 44） | 中心 (333, S+81) |
| BOSS 血条 336×12 + 名字 | y = S+96 起（无 BOSS 隐藏） |
| 4 技能槽 54×54，间距 12 | 居中 x=81/147/213/279，中心离底 36+27 |

- **绑定数据**（HudData，全部来自 rs 真实字段）：hp/maxhp、lv、exp/expNeed、gold、wave、kills、waveLeft、hurtFlash、bossName/bossHp/bossMax、4 个技能（icon/lvl/cdPct/modCount）。
- **交互**：暂停键 → showPause()；其余只读（技能自动释放，没有假按钮）。
- **适配**：顶部按 safeTop()，技能栏按**屏幕底部**定位（不写 640 的绝对 y，KI-009）；中央战斗区不放大面板。

### 3.5 升级三选一 buildLevelUp（最高优先级）
- **区域**：全屏遮罩 → 主面板（340 宽，**高度 = 标题 64 + 3 张卡 + 底部 58**，自动居中）→ 三张 **310 × 92~132 纵排等卡**（间距 10）→ 底部「跳过（+8 金币）」。
- **每张卡**：左侧 6px 类别色条 + 48 图标 + 名称(16) + 类别 chip + 数值(11) + 描述(10，最多 3 行) + 底部状态(9)。
- **绑定数据**：CardData（五类奖励：新技能 / 技能强化 / 黑科技 / 道具 / 属性）——标题、类别、具体数值、一句话效果、叠加/上限状态、图标。
- **交互**：整卡可点（触控面积 310×≥92）；按下整卡压暗一档；点选 → pickReward(i) 执行真实升级；跳过 → pickReward(-1)（真实 +8 金币）。
- **适配**：卡片高度按可用高度 92~132 自适应；面板高度跟随内容。

### 3.6 暂停 / 构建面板 buildBuildDrawer
- **区域**：遮罩 → 底部抽屉（宽 360，高 min(470, VH-S-18)，贴屏幕底）→ 标题 + 页签（4×78×36，热区 44）→ 内容区（技能手风琴 / 道具卡 / 属性网格 / 逐行文本）→ 底部 主菜单 / 装黑科技 / 继续。
- **绑定数据**：技能（名称/等级/伤害/冷却/已装黑科技）、黑科技、道具（人话 + 数值 + 来源）、属性（总值 + 相对基础加成，正绿负红）。
- **交互**：页签切换、技能行展开/收起、主菜单、装黑科技、继续（恢复战斗）。

### 3.7 黑科技安装 buildInstall
- **区域**：全屏面板 → 标题 + 操作提示 → 4 个技能行（316×60，每行 3 个 74×40 槽）→ 背包（3 列 × 1~2 行）→ 合成区（3 同名 → Ⅱ）→ 效果说明条（+卸下）→ 返回/完成。
- **绑定数据**：技能与已装模块、背包模块（同名不同份独立选中）、可合成项、兼容性、手里模块的效果说明。
- **交互**：点背包项拿起 → 点槽位装上/替换；点已装模块拿起 → 可移动/卸下；合成按钮。
- **适配**：PH < 620 时切 **compact**（行高 52、背包一排 3 个），保证 360×640 不打架。

### 3.8 技能替换 buildReplace
- 全屏面板 → 新技能卡（金色描边）→ 4 个已拥有技能行（名字 + 黑科技退回提示 + 替换 chip）→ 底部「放弃这个技能」。

### 3.9 二次确认 buildConfirm
- 屏幕居中 312×196 面板，标题 + 两行说明 + 取消 / 危险确认（136×48 each）。

### 3.10 波间商店 buildShop
- **区域**：标题条（含金币）→ 4 行货架（336 宽，行高 64~84 **按可用高度自适应**）→ 下一波提示 → 已有道具网格（贴底，8 列）→ 底部 刷新 / 下一波。
- **绑定数据**：货位（名称、两行说明、价格、已购、锁定、稀有度、已持有数）、金币、刷新价、下一波时长/是否 BOSS。
- **交互**：点行 = 购买；锁图标（视觉 32 / **热区 44**）= 锁定；刷新；下一波。
- **状态色**：普通 = panel、高级道具 = 紫框、黑科技 = 青框、回复 = 绿框、属性 = 蓝框、已购 = well + 半透明 + 「已购买」。

### 3.11 结算 buildResult
- **区域**：标题条 → 结果大字（通关/倒下）→ 4 个统计卡（2×2，163×60）→ 金币/种子一行 → 本局构筑列表（每行 38）→ 底部 主界面 / 再来一局。
- **绑定数据**：存活时间、击杀、最高等级、波次（胜利 20/20、失败 第 N/20）、金币、种子、本局技能（名称 Lv + 已装黑科技）。

## 4. 适配与安全区策略

1. **设计分辨率**：360×640，ResolutionPolicy.FIXED_WIDTH（代码里写死，不依赖编辑器设置）。
2. **安全区**：Safe.ts 优先读 view.getSafeAreaRect()（微信小游戏会给真实值），取不到时用保守常量（顶 28 / 底 10 设计像素）。HUD、标题条、底部按钮、模态面板全部用它。
3. **高度自适应**：所有"贴底"元素按 VH - B - 距离 定位；所有"贴顶"元素按 S + 距离 定位；中间区域（卡片、货架、抽屉）按可用高度 clamp。
4. **纹理过滤**：UI 九宫格全部 NEAREST（Assets.loadUi 里强制），像素边缘不会糊。
5. **九宫格**：52×52、边距 10px。节点尺寸变化只拉伸纯色中段，四角与描边像素不变形（见 ui_kit_overview.png 的 48 / 120×48 / 180×40 三种尺寸验证）。
6. **触控**：主要按钮 ≥44 高（button() 强制）；小图标（锁、页签）都额外挂了 44 的隐形热区。
