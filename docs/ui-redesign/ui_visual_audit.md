> 审查对象：当前 `main`（提交 4522c33）在 **浏览器构建** 下、**360×640 设计分辨率** 的运行截图。

## 1. 主菜单 `360x640-01-menu.png`

| 元素 | 现状（实测） | 为什么影响玩家 | 改法 |
|---|---|---|---|
| 主视觉 | **没有主体**：标题下 40% 画面是一张背景图里的石阶，没有任何角色 | 主菜单不像"游戏海报"，第一眼抓不住注意力；也看不出这是"怪潮+角色"的游戏 | 用现有 `CHARS[0]` 立绘（`Assets.loadPortrait`）做主视觉，整数倍放大到 110–140px，站在标题与按钮之间的舞台上，后面加低强度径向光晕压出纵深 |
| 标题 | 44px 纯白 + 黑描边 + 4px 硬投影，y≈99–160 | 尺寸够，但纯白+粗黑边在深色背景上"发灰"，且与英文副题贴得紧 | 保持 38–42px，正文色改 `#F7E9E0`，投影保留；副题改 10–11px + 加宽字距，位置下移 6px |
| 主按钮 | 268×58，y≈300–358，橙色 | 尺寸够，但页面只有"标题 + 两块按钮"，主按钮不是唯一焦点（标题占比太大、中间空白太多） | 保持 276×54 橙金；把它放在角色与页脚之间，成为"看完角色后的下一步" |
| 次按钮 | 268×52，y≈375–427，深灰 | 与主按钮间距 17px，抢注意力 | 276×48，距主按钮 10px，压暗 |
| 信息 | 页脚两行 10px 灰字（玩法要点 + seed） | 玩法卖点被塞进页脚，等于没展示 | 抽出 3 个信息块（4 技能 / 黑科技构筑 / 20 波），页脚只留 seed |
| 层次 | 背景 → 标题 → 两个按钮 → 页脚 | 中间 220px 空白，视觉重心在标题 | 背景 + 暗角 → 标题 → 角色 → 卖点条 → CTA → 次按钮 → 页脚 |

**验收图**：`screenshots/ui-visual-upgrade/m1/360x640-menu.png`（另 390×844、412×915，以及立绘加载失败回退态）。

## 3. 角色选择 `360x640-03-charselect.png`（M1）

| 元素 | 现状（实测） | 为什么影响玩家 | 改法 |
|---|---|---|---|
