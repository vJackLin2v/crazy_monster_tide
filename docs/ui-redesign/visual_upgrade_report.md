## 2. 背景与一个必须说明的前提

我拿到的设计文档（`docs/ui-redesign/*`）是为**另一款游戏**写的：横向 1280×720、10 页。
本项目的真实情况是：**竖屏 360×640、微信小游戏、Cocos Creator 3.8.6 + TypeScript**。

**我的处理**（也请重点评审这个决策）：
1. **保留竖屏 360×640**，不为了贴合文档把游戏改成横屏；
2. **沿用文档的结构与规则**（信息层级、字号阶梯、热区 ≥44、九宫格组件、状态双通道），按竖屏重排；
3. **不实现文档里有、本游戏没有的功能**（例如文档假设的"装备栏""商店刷新券"等），也不做假按钮；
4. 文档中与竖屏冲突的尺寸（如 1280 宽的三栏布局）一律按"内容优先、可读性优先"重算。

## 3. 视觉系统（M1 定稿，后续所有页面复用）

### 3.1 色板

| 令牌 | 值 | 用途 |
|---|---|---|
| `bg1` | `#131C36` | 页面底色 |
| `bg0` | `#0D1732` | 更深的底（槽、遮罩下） |
| `bg2` | `#1E2A46` | 面板 |
| `bg3` | `#263653` | 次级按钮 / 行 |
| `edge` | `#34496E` | **容器描边** |
| `edgeHi` | `#617DA8` | 高光边 |
| `inkLine` | `#0A0E1A` | **文字描边**（与容器描边拆开） |
| `accent` | `#FFA84B` | 主行动 / 强调（全页唯一橙） |
| `select` | `#61DCE7` | 选中 / 当前 |
| `mint` | `#88D6BC` | 正向 / 治疗 |
| `purple` | `#B68AFF` | 稀有 |
| `red` | `#E04060` | 危险 |
| `cream` | `#F7E9E0` | 主文字 |
| `dim` | `#A8B5CD` | 次文字 |
| `dim2` | `#6D7892` | 弱文字 |

> 旧实现里"面板描边"和"文字描边"共用同一个变量，导致要么黑框太重、要么文字发灰。拆成 `edge` / `inkLine` 是这次最基础的一处修正。

### 3.2 字号阶梯

40（大标题）/ 24（页面标题）/ 19–21（弹窗标题）/ 16（卡片标题）/ 15 / 13（正文）/ 12（数值）/ 11（说明，下限）/ 10（元信息）/ 9（仅极限处）

### 3.3 组件规则
- 所有容器 = 九宫格像素面板（Kenney Pixel UI Pack，CC0，52×52 九宫格，inset 10，NEAREST 采样）
- 按钮：常态深底 / 按下换图 + 文字下沉 2px / 禁用压暗；**热区 ≥44×44**
- 状态必须**颜色 + 形状/文字双通道**（选中=青框+勾选徽标；不兼容=红字；残血=红字+外发光）
- 文字一律 2px 黑描边，标题加 4px 硬投影（像素风不用模糊阴影）

## 4. 各里程碑改了什么

### M1 · 主菜单 + 角色选择
- 主菜单：标题 40px + 英文副题；**9 段渐隐暗角**托住文字；橙色主 CTA 276×56；底部一行 **图鉴 / 成就 / 设置**（各 104×56）。
- 期间按用户反馈改了 3 轮：**去掉主视觉角色**（"太丑"）→ **去掉 3 个卖点条** → **上下留白对齐**（底部留白 = 标题上沿留白 = 68）。
- 角色选择：卡片 124→90 高、立绘 78×90→52×60 整数倍；选中态加**勾选徽标**；详情改四段式（名称/天赋＋－/初始技能/3×2 属性网格）。

### M2 · 战斗 HUD
- 顶部加 **6 段渐隐承载板**（最高 S+92），数字在亮特效上仍可读，但不侵占中央战斗区。
- 倒计时 24→26px；暂停键 34→36 且**上移**（旧版与 BOSS 血条在 y 上互相压，是真 bug）；金币改 16 图标 + 14px 成组。
- **残血态**：<25% 时数值转红 + **柔和外发光**（不是硬边框），共迭代 5 轮才定稿（见 §7 的评审点）。
- 技能栏按 `VH − safeBottom − 63` 锚定；冷却遮罩 alpha 140→120。

### M3 · 升级三选一 + 商店
- 升级卡：数值 11→12、描述 10→11、元信息 9→10；按下只 tint 卡片自身 Sprite（不污染图标）。
- 商店：说明 10→11、价格 chip 11→12。
- **修了一个真实触控 bug**：`lockHit` 是商品行的子节点，Cocos 的 `TOUCH_END` 会冒泡到父节点 → **点锁会同时触发购买**。改为锁单独监听 + `propagationStopped = true`，并用真实点击验证（点锁金币不变、点主体扣款）。

### M4 · 构建抽屉 / 安装 / 替换 / 确认
- 抽屉黑科技页：从"一整片纯文字"改成**结构化两段**（已装 / 背包，图标 + 名称×N + 效果 + 已装 chip）；道具页补空态。
- 安装屏：**新增"不兼容"文字标签**（原来只压暗）、合成候选全列（够 3 给按钮，不够写"还差 N 个"）。
- 替换屏：新技能卡 64→68、chip 改"新技能"、名称 16 / 描述 11。
- 修越界：「卸下」按钮右边缘 172 > 面板半宽 170，**超出 2px**；同时新增 `tools/ui/audit_overflow.cjs` 做系统检查。

### M5 · 结算 + 玩法说明 + 全量回归
- 结算：统计卡 163×60→158×58（间距 8）、数值 18→22px、构筑副文本 9→10。
- 玩法说明：序号 24→26、标题 13→15、解释 10→11、提示 10→11。
- 三档视口 × 16 屏回归 + 越界审计 + 75 秒自动跑图。

## 7. 我自己知道的问题（请重点挑这些）

1. **微信真机安全区从未验证**。浏览器里 `getSafeAreaRect()` 返回全屏，所以现在只有常量兜底（顶 28 / 底 10）。这是唯一没有被证据覆盖的验收项。
2. **主菜单中部留白大**：去掉角色后，标题与按钮之间是一整片背景。是不是应该再填点东西（用真实数据，比如最高波次/最近使用角色）？
3. **抽屉没有滚动**：黑科技超过 6 条只显示前 3+3 并提示"还有 N 个"。
4. **图鉴不做解锁门槛**：现在所有内容都可见（项目本来没有解锁系统，我没有伪造一层）。
5. **成就只存本机**（localStorage），换设备会清零，未做云同步。
6. **HUD 残血红晕参数是手调的**（外扩 6px、alpha 160→14），只在这三种分辨率上看过，没有做更多机型/亮度验证。
7. **结算页构筑超过 4 行不滚动**。
8. **越界审计只查外接矩形**：不查视觉 glyph 贴边、不查控件互相遮挡。
