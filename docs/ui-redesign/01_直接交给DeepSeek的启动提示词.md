## 一、项目背景与任务边界

项目是《像素共鸣：远征》，一款面向微信小游戏的横屏俯视角像素肉鸽游戏。角色、怪物和技能特效已经有大量像素动画素材，当前主要瓶颈是 UI 缺少统一风格、页面布局不够专业、界面像临时拼装。

本次只负责：

1. 免费像素 UI 素材的筛选、下载、盘点和合法使用。
2. 统一 UI 的边框、面板、按钮、字体、状态条、卡片、图标槽和颜色规范。
3. 根据页面布局规范改造当前已有页面。
4. 复用现有角色、怪物、技能、道具素材作为页面内容。
5. 在 Cocos 工程里实现并验证实际 UI，修复横屏、安全区、缩放和触控问题。

明确不做：

- 不修改战斗、伤害、技能、升级、掉落、角色被动、商店经济等游戏业务逻辑。
- 不重新生成、重绘或替换已有角色、怪物和技能特效。
- 不重新架构项目，不升级 Cocos 版本，不删除现有功能。
- 不增加尚未存在的玩法和假按钮。
- 不购买任何素材，不使用必须付费的资源，不绕过付费限制。
- 不把 ASCII 图、Emoji 或通用符号当作最终游戏图标。
- 不以静态 HTML 展示取代真实 Cocos UI。

如果页面已经存在，应在原有页面及组件上改造；只有确认缺少页面时才新增。所有按钮和状态必须连接到当前项目已有功能；如果功能暂未实现，应隐藏该项或明确标为未实现，不得伪造成功反馈。

## 二、必须遵循的素材来源与美术方向

首先查看 `03_免费UI素材与参考链接.md`。主候选是官方 Kenney Pixel UI Pack（CC0）；第二候选是 Kenney UI Pack - Pixel Adventure（CC0）；Foozle Critters Pixel UI 用于学习完整页面如何组织，不能把其整套视觉与 Kenney 素材随意混拼。

下载前必须先浏览每个资源包的预览图，实际检查 ZIP 内容、许可文件和可用组件。优先从官方页面免费下载，选择“Continue without donating”或 itch.io 页面中的 0 元获取方式；不要打开或购买 All-in-1 付费合集。

主风格目标：传统清晰的像素游戏 UI。面板、按钮、卡片、边框应有一致的像素边缘和比例。优先以已选中的一套 UI 组件为主，再少量补齐确实缺失的东西。建议使用深色或中性色面板、清楚的浅色文字、青/蓝选中态、金色稀有/重点状态、绿色生命、蓝紫色经验、红色危险提示；最终颜色应根据下载后的素材与当前游戏画面实际调整，不可硬套颜色导致素材失配。

必须遵守：

- 先建立一张素材总览图或素材清单，再选素材；不要直接批量塞入场景。
- UI 组件尽量来自同一套资源包，或经过统一描边、调色和尺寸处理后再使用。
- 保留原始下载文件，将项目实际使用的文件放入现有项目合适的 UI 资源目录；如无约定，可用 `assets/ui/third_party/` 存放原始第三方文件、`assets/ui/` 存放项目实际使用的整理后文件，但必须先检查现有目录规范。
- 保存素材名称、官方来源 URL、许可证、下载文件名和实际用途。CC0 素材应保留来源记录，但无需强行显示游戏内署名；其他许可需按要求执行。
- 像素图片优先使用最近邻过滤，尽量整数倍缩放。面板需优先使用九宫格/切片，不能拉伸边角。
- 字体使用前核查许可和中文字形覆盖，不得出现方框字、乱码或回退字体风格不一致。
- 所有关键 UI 必须使用实际 PNG/精灵资源和可修改文本，不可拿网站预览图当素材。

## 三、以明确布局实现页面

以 `02_UI页面布局与尺寸规范.md` 中的 1280×720 参考坐标为起点。请逐页按规范实施：

1. 主菜单。
2. 角色选择。
3. 战斗 HUD。
4. 升级三选一。
5. 暂停与设置。
6. 商店与道具。
7. 路线/事件（仅在当前项目已有对应功能时）。
8. 战斗结算。
9. 成长档案/图鉴（仅在当前项目已有对应功能时）。

坐标是 1280×720 横屏设计稿上的参考值，不是固定屏幕像素。必须根据当前工程的设计分辨率、UITransform、Widget、Canvas、适配设置和安全区域方案正确映射，不能把参考坐标直接硬编码成所有设备的屏幕绝对坐标。

优先级：战斗 HUD → 升级三选一 → 主菜单与角色选择 → 商店/结算/暂停 → 其他当前已实现的页面。

布局的详细区域位置、尺寸、卡片数量、按钮大小和注意事项都在 `02_UI页面布局与尺寸规范.md` 中。线框请查看 `04_UI布局线框参考.html`。如果现有业务结构与示意不完全一致，先保留现有功能，再调整布局；不要为匹配示意图而更改玩法。

## 四、页面验收要求

### 战斗 HUD

- 中央战斗区域必须保持开阔，不能用大型 UI 面板盖住玩家和大量怪物。
- 血量、经验、等级、计时、击杀数、Boss 血条、四个技能槽各自层级明确。
- 只显示项目真实存在的数据。
- 技能栏应使用已有技能图标或适当缩略图，并能显示实际等级/状态（如果游戏有该数据）。
- 如果现有游戏有虚拟摇杆，则确保摇杆不遮挡关键战斗区域；没有摇杆就不要凭空加一个。

### 升级三选一

- 三张卡片同尺寸、同边框规则、同信息层级。
- 每张卡有图标、名称、类别标签、短描述、必要的等级/变化信息。
- 文字长度变化不能挤坏卡片。
- 卡片可点击范围足够大，选中态明显，点击事件连接实际升级逻辑。
- 不得用 Emoji 代替技能素材，不得随意生成新的技能插画。

### 主菜单与角色选择

- 主菜单突出标题、已有角色/场景主视觉和主要开始按钮。
- 角色选择必须复用已有角色动画帧；当前选中角色突出显示。
- 角色信息、固定被动、属性及确认按钮布局明确。
- 不展示未实现的转职、解锁或图鉴功能。

### 其余页面

按布局规范执行；没有实际业务功能的页面不要伪装成已完成。尽量复用相同窗口、标题栏、按钮、卡片和状态条组件，避免每个页面长得完全不同。

## 五、移动端与像素质量要求

- 横屏适配微信小游戏，并按当前工程支持的实际分辨率测试。
- 考虑刘海、安全区域和不同长宽比。
- 所有点击区域符合触控习惯，重要按钮不要过小或彼此贴得太近。
- 不依赖鼠标悬停。
- 检查文字缺失、溢出、重叠，图标模糊、九宫格变形，弹窗后层误触等问题。
- 保持像素锐利，避免双线性过滤造成模糊；对所有 UI 页面检查不同缩放下是否出现边缘变形。
- 不让 UI 遮挡技能表现和怪物群，尤其不要把升级/暂停等弹窗以外的界面做成大面积常驻遮罩。

## 六、实际执行步骤

1. 检查项目根目录、现有 UI 场景、脚本、Prefab、素材和适配机制。
2. 输出简洁的现状清单与缺失 UI 列表，然后继续，不需要等待我确认。
3. 访问官方素材页，挑选免费包并核对许可证。能自动下载就下载；如果当前环境网络或下载能力不允许，报告准确链接和文件名，继续用本地资源做已可完成部分，不要虚报。
4. 建立 UI 素材清单与统一视觉规范。
5. 按 P0/P1/P2 顺序先完成战斗 HUD、升级三选一，再完成其他现有页面。
6. 实际启动 Cocos 项目，检查页面并修复问题。不能只靠代码检查或静态 HTML 认定完成。
7. 提供真实运行截图：主菜单、角色选择、战斗 HUD、升级三选一、商店/道具、结算，以及当前项目的其他已实现界面。
8. 执行项目现有构建和测试流程，报告结果。

不能虚报测试成功，不能把线框或静态 HTML 当成交付完成。若某部分无法验证，应明确标记为“未验证”。
