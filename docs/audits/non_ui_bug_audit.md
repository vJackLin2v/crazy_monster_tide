## 2. 已确认并修复

### B1 · 替换技能重复返还模块（P0）

- **根因**：`RunState.replaceSkill()` 已经把旧技能的 mods 放回 `modsBag` 并返回同一份数组；
  `GameRoot` 又执行了一次 `rs.modsBag.push(...back)` → 替换一次 = 模块**翻倍**。
- **证据**：`RunState.ts:242-249`（push + return）、修复前 `GameRoot.ts:283-284`（二次 push）。
- **修复**：删除调用方的 push，返还责任只保留在模型层；`GameRoot.ts` 留日志。
- **测试**：`B1 替换技能后模块总量不变（2 → 2）`、`B1 背包里 multi 只有 1 份`。

### B2 · 跨技能移到空槽造成稀疏数组（P0）

- **根因**：`moveMod()` 跨技能走到"空槽"分支时执行 `b.mods[toSl] = mod`；
  当 `toSl >= b.mods.length`（例如目标技能 0 个模块、玩家点第 3 槽）会生成 `[empty, empty, mod]`。
  之后 `calcSkill` 迭代到 `undefined` → `baseOf(undefined)` 崩溃；`mods.length` 也会与 UI 槽位不符。
- **修复**：空槽一律 `push`（保持连续），并先检查目标技能 `< MAX_SLOTS`；占用槽才做交换。
- **测试**：`B2 跨技能移动到空槽后数组连续（length=1）`、`B2 无 undefined 空洞`。

### B3 · installAt 缺少模型层校验（P1）

- **修复前**：只判 `slot` 是否存在；`mid` 非法、背包没有、不兼容、`target` 越界都能写进状态，
  且是"先改背包再改槽位"——中途抛错会留下半成品。
- **修复**：**先全部校验、后一次性提交**：技能槽/模块槽范围、模块存在、背包确实持有、`isCompatible`、
  槽位已满、叠加上限；任一失败抛错且不改任何状态。
- **测试**：`B3 四种非法安装都抛错（4/4）`、`B3 失败时背包与技能槽完全不变`。

### B4 · 强化模块突破 max（P1）

- **根因**：`canInstall/installAt` 用 `modCount(sk,mid) >= max` 判断，而 `_2` 一次贡献 **2 份**；
  `fan`(max 2) 已有 1 份时仍允许装 `fan_2` → 实际 3 份 > 2。
- **修复**：改为 `现有份数 + modPower(mid) <= max`（被顶掉的那份先扣掉）。
- **测试**：`B4 已占 1 份 + 强化 2 份 > max(2) 时拒绝安装`。
- **遗留规则矛盾（待决策）**：`max <= 2` 的模块（扇射/复读机/冷静/传染/点名/渡劫/超载/吸血/割韭菜/刺猬）
  **永远不可能持有 3 个同名**，因此"3 个同名 → Ⅱ"对它们不可达。二选一：
  ① 允许 max≥3 才能出现在合成候选；② 合成门槛按"该模块 max"缩放（如 max2 → 2 个即可合成）。
  **本报告不擅自改数值。**

### B6 · 连锁模块不生效（P1）

- **证据**：原生连锁 `for (let j = 0; j < 2 + rt.bounce; j++)`（`Battle.ts:721`）只吃反弹；
  弹体链式分支 `if (b.chain > 0) { b.chain--; ... b.life = 0; break; }` 无论几份都只跳 1 次。
- **修复**：原生连锁改为 `2 + rt.bounce + rt.chain`；弹体链式改为 `while (b.chain > 0)` 连续跳（70% 伤害、命中表去重）。
- **遗留**：`传染` 的 `max=2`，所以最多 +2 跳。**无自动化单测**（战斗循环未单测化），建议后续把 `fireSkill` 的跳数决策抽成纯函数再补测。

### B7 · 落雷只有特效没有伤害（P1）

- **证据**：修复前 `if (rt.thunder > 0 && chance(...)) this.addVfx('feedback/hit/shock-hit', ...)` —— 只有表现。
- **修复**：触发后对落点半径内敌人结算 `dmg × mul`，并用 `noThunder` 参数**阻断递归触发**。
- **数值来源**：`docs/systems` 未规定 → 采用**候选值** `半径 60 / 倍率 0.5`，写进 `Balance.thunder`，
  可 `__balSet({ thunder: { radius: 70, mul: 0.6 } })` 热调，**待负责人确认**。
- **风险**：群怪环境下雷击会被高频触发，可能偏强（未做压力测试）。

### 3.2 唯一模块也能合成（用户 2026-10-29 追加：「要，但削弱数值，合成收益必须递减」）

| 模块 | 基础值（削弱后） | Ⅱ 效果（1.6 份） | 说明 |
|---|---|---|---|
| 吸血 vamp | **4%/份**（原 6%） | **6.4%** | 比"两份普通 = 8%"低，但省 1 槽 |
| 割韭菜 harvest | **1 HP/份** | **1.6 HP** | 同上 |
| 刺猬 thornmail | **6 点/份**（原 8） | **9.6 点** | 同上 |

**两条计数分开**（避免"占位"和"效果"混为一谈）：

| 概念 | 函数 | 普通 | Ⅱ |
|---|---|---|---|
| 占位 / 合成判定 / 上限 | `modPower()` | 1 | **2**（仍按 2 份算，防止突破 max） |
| 实际效果 | `modEffect()` | 1 | **1.6**（`TIER2_EFFECT`） |

⇒ 「越高级收益越低」在数值型模块上由 1.6 < 2 保证；整数型（子弹数/跳数）无法出半份，
其递减体现在「3 份普通 → 合成后按 2 份计」这一步（3 → 2 本身就是递减）。

同时**B4 的规则矛盾**按方案 A 处理：
- 可合成模块的 `max` 统一提到 **3**（扇射/复读机/冷静/传染/点名/渡劫/超载），凑得齐 3 个就能合成 Ⅱ；
- `unique`（吸血/割韭菜/刺猬，max=1）**不进合成候选**，安装屏不再出现"还差 1 个"却永远凑不齐的假提示；
- 模块描述同步改写（"每份 +1 枚 / +1 次 / +10% / +10% 减速"），做到 UI 与实现一致。
